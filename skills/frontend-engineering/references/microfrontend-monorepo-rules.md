# 微前端与 Monorepo 专项规则

## 一、边界识别

确认主应用、子应用、共享包、独立构建、部署单元、路由所有权、认证入口、公共依赖和通信协议。Monorepo 不等于微前端；多个包也不代表可独立部署。

## 二、运行时隔离

检查样式、全局变量、事件、路由、Store、缓存、LocalStorage、Cookie、SSE/WebSocket、定时器和 DOM 容器是否隔离；子应用卸载必须清理副作用。

## 三、共享依赖与版本

Module Federation、single-spa、qiankun 等需检查 Shared/Singleton、版本范围、加载失败、重复框架实例和灰度兼容。公共组件和类型包变更需评估所有消费者。

## 四、契约、发布和回滚

明确主子应用消息/API 契约、错误隔离、超时、降级、独立发布、资源域名、CSP、缓存、监控、灰度和回滚。避免单个子应用故障拖垮主应用。

## 五、测试

至少验证独立运行、集成运行、路由跳转、登录态、卸载重挂载、版本混用、资源加载失败和回滚。多个 Agent 或团队同时修改时明确目录和集成人。
