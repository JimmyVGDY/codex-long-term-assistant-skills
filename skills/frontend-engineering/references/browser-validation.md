# 浏览器验收操作流程

## 选择入口

对实际前端行为、布局或交互作验证时使用。先读取项目的测试入口、服务启动方式和当前宿主可用的浏览器工具；沿用既有测试，遵守工具的访问方式，不通过其他驱动、调试端口或隐藏状态绕过其限制。

只读分析不自动启动或重启服务。执行写表单、支付、发送消息或其他业务副作用前，核对当前任务的实际环境和授权；优先使用合成数据和隔离服务。

## 服务和页面就绪

1. 记录目标 URL、服务身份、版本/构建、环境及预期页面。已有服务先识别来源，不因端口占用就杀进程或替换服务。
2. 确需启动时，使用项目实际入口，记录工作目录、参数、进程与子进程归属。参数按数组传递；日志、等待和执行时间有界。
3. 端口可连接只是线索。通过已知健康响应、页面内容或版本标识确认正确服务；不要将别的本地服务当作目标。
4. 以目标元素、数据状态或业务可操作条件判断页面就绪。长连接或后台请求页面不依赖统一的网络空闲条件，不用固定延迟冒充就绪断言。

## 观察、操作、断言

从实际渲染 DOM 或截图发现可用控件和定位方式，不猜测未观察到的选择器。优先语义角色与稳定标签，操作后等待可观察的状态变化。

按改动范围选择正常、加载、空、错误、禁用、重复点击、取消、刷新、路由切换和竞态等场景。断言界面和相关业务状态；截图提供视觉证据，但按钮出现并不证明保存或权限规则生效。Mock、浏览器实际交互和真实后端集成分别记录。

沿用[前端验证矩阵](../assets/templates/FRONTEND_VALIDATION_MATRIX.template.md)，需要浏览器验收时附加[浏览器证据附表](../assets/templates/browser-evidence.md)。附表补充服务身份、就绪断言、操作、结果和资源归属，旧矩阵仍适用于不需要浏览器的任务。

## 失败、取消和回收

失败时保留有用且脱敏的错误、截图和复现步骤；不采集完整 Cookie、凭据、敏感表单或无关网络响应。区分应用失败、测试环境不就绪、工具权限拒绝和未完成，不把未执行的场景填成通过。

退出、失败和取消均仅关闭本次创建的浏览器上下文、服务器及子进程。不能仅按进程名或端口批量结束用户服务；无法确认归属时报告剩余资源和具体原因。Windows 路径与进程管理按实际宿主验证，不将其他平台通过当作本机通过。

重新验证只覆盖修复影响的场景；相同条件没有新信息时不无限重试。交付说明构建、浏览器、后端集成、设备覆盖和未验证项，不能用其中一层代替其他层。

## 维护者合成样例

仓库内的 `tests/fixtures/quality_browser.py` 可为本流程提供公开合成页面。使用现有 Python，以 `--lease <已存在外部目录/本次租约.json> --lifetime 600` 启动；它只监听回环地址，前端与 API 使用独立随机端口，返回实例、角色和进程身份。通过健康响应与返回身份一致后再打开页面，覆盖静态内容、正常/空/错误请求、慢请求取消及重复提交。

只对本次创建的租约运行同一脚本的 `--lease <原租约> --stop`；脚本核对实例和进程身份后停止自己的服务。不要展示或复制租约中的 owner_token。已有服务保持运行；测试中的另一合成服务只能证明隔离案例，不能当作实际用户服务验收。这个辅助器不安装依赖、接管项目服务或证明生产后端已验证。
