# 通用前端核心规则

## 一、项目与运行边界识别

开始前确认：

- 项目类型：静态站点、SPA、MPA、SSR、SSG、ISR、PWA、微前端或混合模式；
- 框架、元框架、UI 库、状态管理、路由和数据获取方案；
- JavaScript / TypeScript、`tsconfig`、Node 版本和浏览器目标；
- npm / pnpm / yarn / Bun、锁文件、Workspace 和安装脚本；
- Vite、Webpack、Rspack、Rollup、Parcel、esbuild、SWC、Babel 等构建链；
- 单元、组件、E2E、视觉回归和浏览器测试工具；
- 浏览器端、SSR 服务端、构建时、Edge、Worker 和 BFF 代码边界；
- 部署基础路径、反向代理、CDN、缓存和新旧资源兼容。

事实来源依次优先：当前任务、`package.json`、唯一有效锁文件、构建配置、入口与路由、源码结构、CI/CD 和实际构建输出。不能仅凭目录名猜测框架。

如存在多个锁文件、多个前端应用或混合框架，应先报告冲突和目录边界，不得直接全量安装、升级或格式化。

## 二、组件、模块和状态边界

区分页面容器、业务组件、展示组件、通用组件、API Client、领域适配层和纯函数。区分局部状态、URL 状态、跨组件状态、服务端状态、持久化状态和派生状态。

主动检查：

- 状态是否存在多个不一致来源，派生状态是否被重复存储；
- Store / Context / Service 是否无边界承载全部数据；
- 渲染、计算值、Getter 或不合适生命周期中是否存在写操作和隐式副作用；
- 组件卸载后请求、定时器、事件监听、Observer、SSE、WebSocket、Worker、Object URL 和插件实例是否释放；
- 全局事件总线、全局变量、模块级单例和缓存是否造成跨页面、跨用户或跨请求污染；
- 大对象、敏感对象、DOM、连接和不可序列化对象是否进入持久化状态。

简单项目不为形式引入复杂状态框架；复杂项目则应保持单向、可追踪、可测试的数据流。

## 三、接口、异步、竞态和一致性

覆盖正常、加载、空、错误、禁用、部分成功、恢复、离线和弱网状态。检查：

- 超时、取消、重试、重复点击、页面切换和组件卸载；
- 搜索、分页、联想、自动保存和筛选中的旧请求晚返回；
- 防抖、节流、AbortSignal、请求序号和最新结果校验；
- Token 失效、权限不足、统一错误语义和可观测性；
- 字段、枚举、时间、时区、金额、分页、排序、错误码和版本契约；
- 客户端缓存、服务端缓存、乐观更新、回滚和最终一致性；
- GraphQL/REST/BFF 的缓存键、错误模型、部分数据和重试语义。

非幂等操作不盲目重试。前端防重复不能替代后端幂等。不得吞异常、无限重试、反复弹窗或制造日志与埋点风暴。

## 四、路由与导航状态

检查路由参数、查询参数、重定向白名单、页面复用、滚动恢复、未保存表单、动态路由、账号切换和权限缓存残留。URL 中不得泄漏 Token、隐私、内部路径和敏感查询条件。

## 五、表单、列表和文件

- 表单：初值、回显、脏状态、跨字段/异步校验、金额精度、时区、提交中禁用和失败恢复；
- 列表：空状态、页码/游标、总数变化、稳定 Key、批量选择、虚拟滚动和筛选后状态；
- 文件：大小、类型、签名、分片、断点、进度、取消、重试、文件名编码、下载权限、预览内存和 Object URL 释放。

前端文件、金额和字段校验只属于体验层，服务端和存储必须独立校验。
## 六、运行载体、Workspace 与技术栈冲突

除浏览器外，还应识别 WebView、PWA、Extension、Electron/Tauri Renderer、Edge/Worker 和 SSR 运行时。相同 TypeScript 文件在浏览器、Node、Edge、主进程或原生桥中的权限和 API 完全不同，不能只按文件扩展名判断。

Workspace/Monorepo 场景必须记录：根目录、目标应用目录、共享包、构建入口、独立部署单元和锁文件所有权。根目录检测结果不能自动覆盖每个子项目；共享 UI/类型包变更要识别全部消费者。

检测到多个框架、多个锁文件或前后端依赖混合时，先划分应用和运行边界，再决定 Skill 与验证范围，禁止全仓库无差别升级或格式化。
