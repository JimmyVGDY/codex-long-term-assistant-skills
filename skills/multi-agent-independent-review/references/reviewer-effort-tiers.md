# Reviewer 范围与成本档位

成本档位只控制 Reviewer 数量、读取范围和最大工作量，不直接等同于执行流程或模型推理强度。模型选择见 `reviewer-model-routing.md`。

| 档位 | 适用范围 | 默认 Reviewer 数 | 上下文原则 |
|---|---|---:|---|
| `economy` | 局部、低风险、证据充分，或只需一个机械核验维度 | 0～1 | 只读摘要、差异统计和目标 hunk；不扩大调用链 |
| `balanced` | 普通核心行为改动 | 1～2 | 改动文件完整上下文与直接上下游；按职责分片 |
| `deep` | 安全、迁移、核心状态、跨服务或生产高风险 | 2～3 | 允许关键调用链和一次冲突裁决；仍禁止无边界全库扫描 |

## 选择规则

- 小任务已经有直接定向测试和主 Agent 自查时，可以不启动子 Reviewer。
- 每个 Reviewer 必须有唯一职责；职责重叠时合并或删除，而不是增加人数。
- `deep` 默认使用 `terra-medium`，只把命中高风险条件的 1 个关键维度升级到 `terra-high`。
- 第二轮只复核受集中修复影响的维度，默认不超过 2 个 Reviewer；第三轮不是默认流程，只在显式放宽硬上限后用于 1 个阻塞裁决 Reviewer。
- 子 Agent 只接收最小审查包，只返回结构化 findings、已检查范围、未验证项和模型运行证据。
- 成本档位不能降低证据标准；证据不足时应标记未验证，而不是输出伪确定结论。
