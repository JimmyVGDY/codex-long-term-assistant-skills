# Reviewer 强度与成本档位

| 档位 | 适用范围 | 默认 Reviewer 数 | 轮次和上下文原则 |
|---|---|---:|---|
| `economy` | 局部、低风险、证据充分的单一维度 | 1 | 只读统一审查包，短摘要；不扩大调用链 |
| `balanced` | 普通核心行为改动 | 1～3 | 阅读变更完整上下文和直接上下游；结构化输出 |
| `deep` | 安全、数据迁移、核心状态、跨服务、生产高风险 | 2～6 | 允许更深调用链和第二意见，但仍受总预算和轮次限制 |

## 选择规则

- 成本档位控制 Reviewer 数量、范围和最大工作量，不代表可以降低证据标准。
- 测试交付、格式和局部兼容通常可使用 `economy/balanced`；安全、数据契约和核心状态通常使用 `deep`。
- 主协调 Agent 必须记录每个 Reviewer 的档位和唯一职责。
- 两个平台的子 Agent 都使用独立上下文；只传最小审查包，避免把父会话全部复制进每个 Reviewer。
- 子 Agent 最终只返回问题、证据、未验证项和建议验证；不要回传完整工具日志或冗长探索过程。
