# 触发条件、风险分级与 Reviewer 分工

## 本文件目录

- 四、触发条件与风险分级
- 五、专业 Reviewer 分工

## 四、触发条件与风险分级

### 3.1 原则上触发

- 后端、前端、公共库或共享组件代码变化；
- Worker、调度、脚本、导出和数据处理逻辑变化；
- 数据库迁移、数据修复或消息契约变化；
- 运行配置、权限规则、序列化和公共状态变化；
- 核心业务、资金、权限、生产、历史兼容、高并发或数据一致性链路。

### 3.2 通常不触发

- 纯提交拆分；
- 仅修正提交信息；
- 不改变行为的文字、标点或排版；
- 未修改代码的只读分析；
- 已明确属于低风险且当前任务卡豁免的非行为变更。

### 3.3 风险级别与 Reviewer 数量

| 风险 | 典型场景 | 建议 Reviewer |
|---|---|---:|
| 低 | 局部、低频、无共享契约的小修复 | 1～2 |
| 中 | 单模块业务修改、数据库或异步链路 | 3～4 |
| 高 | 跨模块、公共组件、权限、并发、兼容 | 5～6 |
| 关键 | 生产、资金、数据迁移、核心状态机 | 第一轮 6，按需追加专项复核 |

“尽可能多开”应理解为：在风险、平台能力、Token 成本和职责独立性允许时，尽量覆盖不同审查维度；不是固定把数量开到上限。

## 五、专业 Reviewer 分工

### 4.1 功能与业务口径 Reviewer

检查：

- 目标问题是否真正解决；
- 正常、异常、补偿和失败路径；
- 业务计算、字段含义和状态流转；
- 是否只修表现没有修根因；
- 是否改变既有业务口径；
- 是否遗漏关键分支和不可达分支。

推荐 Agent：`cp_review_functional_business`。

### 4.2 回归与兼容 Reviewer

检查：

- 未修改正常路径是否保持原行为；
- 旧接口、旧前端、旧 Worker 和旧实例；
- 旧数据、旧缓存、旧消息和历史序列化；
- 公共方法、默认值、枚举和错误码；
- 灰度期间新旧版本共存；
- 修复 A 是否间接破坏 B。

推荐 Agent：`cp_review_compatibility_regression`。

### 4.3 权限与安全 Reviewer

检查：

- 认证、接口权限、数据权限和租户隔离；
- 水平和垂直越权、ID 枚举、资源归属；
- SQL / 命令注入、SSRF、路径穿越、XSS、CSRF；
- 文件上传下载、反序列化、敏感信息和日志脱敏；
- 新接口、新入口和默认配置是否绕过安全边界。

推荐 Agent：`cp_review_security_access`。

### 4.4 性能与资源 Reviewer

检查：

- SQL 数量、N+1、全表扫描、索引失效和长事务；
- 远程调用、Redis、MQ、文件、NAS 和对象存储 I/O；
- 线程、协程、进程、连接池、队列、缓存和临时文件；
- 大对象复制、重复序列化和高频日志；
- 开销是否位于高频路径；
- 开销是否随用户、任务、文件或数据量线性或更快增长；
- 无界并发、队列、缓存和重试。

推荐 Agent：`cp_review_performance_resources`。

### 4.5 数据与契约 Reviewer

检查：

- 数据库字段、索引、唯一约束、事务和锁；
- API 请求、响应、错误码和幂等键；
- Redis Key、TTL、序列化和缓存一致性；
- MQ 消息版本、ACK、重试、死信、顺序和重复消费；
- 文件格式、对象 Key 和历史数据兼容；
- 各层字段含义和成功边界是否一致。

推荐 Agent：`cp_review_data_contract`。

### 4.6 状态、并发与交互 Reviewer

检查：

- 空值、空集合、零值、最大最小值和时间边界；
- 重复提交、重复点击、重复回调和幂等；
- 并发竞争、锁顺序、超时、重试、取消和中断；
- 部分成功、部分失败、恢复和最终一致性；
- 页面刷新、路由切换、加载、空、错误和禁用状态；
- 异步竞态、资源释放和隐式依赖。

推荐 Agent：`cp_review_state_concurrency`。

### 4.7 测试与交付 Reviewer

检查：

- 最低定向验证是否能证明修改行为；
- 测试是否覆盖关键正常、异常和边界路径；
- 测试是否过度 Mock、依赖执行顺序或污染环境；
- 构建、导出、迁移和运行证据是否真实；
- CHANGELOG、提交边界、文档和实际差异是否一致；
- 失败、历史失败、未验证项是否被隐瞒。

推荐 Agent：`cp_review_test_delivery`。
