# 停止条件、结构化输出、台账与长期记忆

## 一、停止条件

正常停止：阻塞问题已解决；高等级问题已解决或明确接受；最低定向验证有效；相关契约复核完成；差异稳定；未验证项已记录。

受限停止但不能标记通过：达到深度、轮次、修复、Reviewer 总量、Terra High 或平台并发上限；环境/权限缺失；冲突无法裁决；继续处理会扩大任务边界；需要用户决定业务口径或风险接受。

以下情况直接停止追加 Reviewer：

- 上一轮对相同 packet 无问题通过；
- 相同 Reviewer 已审过相同 packet 且没有明确第二意见理由；
- 新一轮不会检查新范围、验证新假设或裁决阻塞冲突；
- 预计新增信息不足以改变门禁结论。

默认最多 2 轮 post review。第三轮仅属于兼容硬上限，必须显式放宽，并且只用于 1 个仍然阻塞的定向裁决 Reviewer。

## 二、Reviewer 结构化输出

Reviewer 使用 `review-result.schema.json`，至少包含：

- Reviewer、轮次、功能边界、packet hash；
- 请求与实际模型、推理强度和分配状态；
- 隔离等级；
- 已检查范围与未验证项；
- 结论；
- 发现的严重等级、证据、位置、触发条件、影响、根因、修复边界和验证方式。

同一根因合并，默认最多 8 个根因组；不回传完整 diff、原始长日志或内部推理。没有发现也必须列出检查范围和证据缺口。

## 三、主协调台账

记录 Reviewer 职责、模型档位、状态、packet hash、问题去重关系、根因组、阻塞、修复/验证/复核状态、隔离证据和剩余预算。原始结构化结果保存在 `reviews/<任务>/round-N/`，主进度只保存索引和归并结论。

运行时档位高于请求或超出批准组合时标记 `mismatch`；关闭台账前必须显式确认该策略违规，不能静默通过。

## 四、长期任务记忆

启用 `$long-running-task-memory` 时采用事件驱动检查点，不为每次派发和返回重复写文档。至少在以下四个可恢复节点持久化：

1. 审查包、计划、预算和第一轮派发已确定；
2. 本轮结果收齐并完成根因归并；
3. 集中修复和受影响验证完成；
4. 最终定向复核和门禁结论形成。

只有主协调 Agent 写共享记忆；Reviewer 只返回结构化结果或写入明确分配的独立报告。
