# 不同文档类型与多方案对比

## 本文件目录

- 七、不同文档的关键约束
- 八、多方案对比

## 七、不同文档的关键约束

### 7.1 技术方案

至少回答：

- 现状和根因是什么；
- 目标和非目标是什么；
- 有哪些候选方案；
- 推荐方案为什么适合当前阶段；
- 对接口、数据、性能、安全和兼容有什么影响；
- 如何实施、验证、灰度和回滚；
- 什么条件下需要升级方案。

### 7.2 架构设计

至少明确：

- 业务和系统边界；
- 模块或服务职责；
- 数据所有权；
- 同步和异步交互；
- 事务和一致性边界；
- 容量、扩缩容和故障隔离；
- 权限、安全、可观测性和部署；
- 成本和演进路线。

### 7.3 实施计划

每个阶段应包含：

- 目标；
- 输入和前置条件；
- 修改范围；
- 输出；
- 验证；
- 风险；
- 停止条件；
- 回滚点；
- 依赖关系。

不能把尚未确认的日期和人员写成确定承诺。

### 7.4 API 设计

至少明确：

- 接口用途、调用方和权限；
- 路径、方法、版本和幂等；
- 请求、响应、错误码和示例；
- 字段含义、类型、必填、长度、枚举、精度和时区；
- 分页、排序、过滤和批量上限；
- 兼容策略、限流、超时和审计；
- 敏感字段和数据权限。

### 7.5 数据库设计

至少明确：

- 业务对象和数据所有权；
- 表、字段、类型、默认值和约束；
- 主键、唯一约束和索引；
- 查询模式和执行计划考虑；
- 事务、锁、并发和幂等；
- 历史数据、迁移、新旧代码共存和回滚；
- 数据保留、归档和审计。

### 7.6 部署与运维文档

必须区分：

- 环境和目标实例；
- 前置检查；
- 制品、配置和密钥；
- 部署步骤；
- 数据库和中间件操作；
- 健康检查和业务验收；
- 监控指标和观察期；
- 停止条件和回滚步骤；
- 操作记录。

命令成功不等于功能生效。

### 7.7 故障报告

按证据区分：

- 现象和影响；
- 时间线；
- 已知证据；
- 可能原因和验证过程；
- 已确认根因；
- 临时止血；
- 正式修复；
- 恢复验证；
- 防复发措施；
- 未验证项和后续观察。

根因未确认时，不得为了完整性强行给出唯一根因。

### 7.8 代码审查报告

建议包含：

- 功能理解；
- 审查范围和基线；
- Bug、空指针、并发、事务、SQL、性能、安全、兼容和维护性问题；
- 每个问题的证据、等级、影响和建议；
- 阻塞项和非阻塞项；
- 未阅读或未验证范围；
- 最终结论。

### 7.9 进度和交付报告

必须区分：

- 已完成；
- 进行中；
- 未开始；
- 受阻；
- 已验证；
- 未验证；
- 已提交、已推送、已部署、已重启和已生效。

不得只写“优化完成”，应列出实际交付、验证证据和遗留风险。

### 7.10 面向管理层的报告

优先表达：

- 业务背景和目标；
- 当前状态；
- 核心结论；
- 影响范围；
- 方案和资源；
- 风险和控制；
- 计划和决策事项。

保留必要技术依据，但避免无助于决策的大段源码和底层细节。

## 八、多方案对比

多个方案至少比较：

| 维度 | 说明 |
|---|---|
| 业务适配 | 是否满足当前需求和口径 |
| 实现成本 | 开发、测试、迁移和培训成本 |
| 上线风险 | 变更范围、停机、数据和回滚风险 |
| 性能与容量 | 延迟、吞吐、资源和扩展能力 |
| 兼容性 | 旧接口、旧数据和新旧版本共存 |
| 安全 | 权限、数据和供应链风险 |
| 可维护性 | 复杂度、可观测性和团队能力 |
| 运维成本 | 部署、监控、故障和资源成本 |
| 回滚难度 | 是否能快速恢复原链路 |
| 适用阶段 | PoC、初期、增长期或成熟期 |

对比后必须给出：

- 推荐方案；
- 推荐理由；
- 不推荐其他方案的原因；
- 适用前提；
- 重新评估或升级条件。
