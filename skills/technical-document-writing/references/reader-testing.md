# 陌生读者测试

## 何时使用

安装、部署、恢复手册，跨团队架构或决策文档，或明确要求验证“别人能否照做”的正式文档，适合在草稿稳定后使用。普通标点、术语、CHANGELOG 和简单说明仍按原质量清单检查，不自动增加读者任务。先从已有材料识别受众和用途，只澄清会改变结果的缺口。

## 冻结测试输入

保存文档版本或摘要，确定读者应完成的任务及关键问题。操作型文档通常围绕以下五点裁剪问题；架构文档可将操作问题替换为决策依据和替代方案。

| 关注点 | 读者需要回答的内容 |
|---|---|
| 适用范围 | 对哪个版本、环境和角色有效，哪些情况不适用 |
| 前置条件 | 需要哪些输入、权限、配置及外部依赖 |
| 实际步骤 | 先做什么，输出应是什么，如何判断可以继续 |
| 失败恢复 | 在哪里停止，恢复什么，是否需要升级处理 |
| 成功边界 | 哪些证据证明成功，哪些事项仍未验证 |

由作者或维护者预先确定关键问题的事实标准，保留在读者输入之外。不要根据读者回答反向改标准。可以使用[读者测试记录](../assets/templates/reader-test.md)，不必为简单文档复制整个模板。

## 独立阅读

在授权和现有预算内，给一个不继承作者对话的读者仅提供文档、目标受众和问题。读者返回答案、依据段落、歧义和缺失前提；文档未提供的信息明确为不可回答。不要提供期望答案、此前评审结论、聊天历史或提示性修复建议。

本步骤验证文档本身的充分性，读者不通过搜索源码、联网或补写流程来替作者弥补缺口。实际事实、命令和接口仍由维护者另行对照源码或权威资料验证。读者理解正确不等于文档事实正确。

无法获得独立读者时，保留作者自查结果和未验证项；不得把同一上下文的自我问答标成独立测试。独立上下文也不证明系统只读；隔离等级依实际宿主证据说明。

## 修订与结束

收齐本轮问题后区分文档遗漏、读者误解、事实错误和范围外需求，集中修订相应段落，再测试受影响的问题。保留失败版本和对应摘要。相同输入、无新信息时不重复开读者；达到现有任务预算或仍缺关键输入时，报告具体未完成项。

关键问题均能依据文档正确回答、已知阻塞缺口关闭后，可以报告读者理解测试通过。仍需分别说明事实核验、真实操作验证和未覆盖读者类型；不据此宣称部署成功。

例如“更新后确认正常”缺少可执行标准。改进应由真实项目材料给出适用版本、前提、检查入口、预期结果及失败处理，不能编造一条看似完整的命令。
