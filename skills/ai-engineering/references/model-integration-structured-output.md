# 模型集成、流式响应与结构化输出

## 调用契约

确认模型名称、能力、输入类型、上下文窗口、输出上限、采样参数、区域、超时、限流、并发、计费和内容策略。SDK 默认值不能代替显式业务约束；不依赖响应头或文档字段推断实际传输顺序和业务完成时间。

## 结构化输出

- 优先使用提供方原生 Schema/工具协议，并在本地再次校验；
- Schema 明确必填、类型、枚举、范围、长度、未知字段和版本；
- 修复非法输出时限制轮次并保留原错误，不形成无限“让模型修模型”的循环；
- 解析成功后仍执行权限、状态、引用和业务规则校验；
- Schema 变更评估旧模型、旧缓存、旧任务和旧消费者兼容。

## 流式响应

检查首包、增量事件、完成标记、错误事件、取消、重连、重复、顺序、UTF-8 边界、结构化片段和最终聚合。连接结束不等于生成成功；必须以协议终态和完整输出校验为准。

## Provider 隔离与降级

内部业务状态和错误分类不应直接绑定单一 Provider。多模型降级必须声明能力差异、数据地域、价格、内容策略、上下文、Schema 和质量门槛，不能只按“请求失败就换模型”。结果不确定时进入对账或人工处理，不盲目重复付费提交。
