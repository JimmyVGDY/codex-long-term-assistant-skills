# 通用后端核心规则

## 一、项目与运行边界识别

先确认当前目录承担 API、业务服务、网关、Worker、调度、批处理、桌面主进程还是其他服务端职责。证据优先级为：任务约束、项目上下文、构建与锁文件、入口和源码、容器与 CI、实际运行环境和日志。

至少识别：

- 语言、运行时、框架和版本；
- 进程、线程/协程、Worker 与部署单元；
- 数据访问、缓存、消息、文件和外部服务；
- 构建、类型、Lint、测试和启动入口；
- 客户端、服务端、AI 与基础设施边界。

不得因为文件扩展名或单个依赖推断完整技术栈，也不得把一个应用的框架语义套入同仓库其他应用。

## 二、接口、业务和对象边界

后端接口层负责协议解析、基础校验、认证结果接收、服务调用和响应映射；应用或业务层负责规则、状态、权限、幂等和事务编排；数据访问层负责查询、持久化、锁和批量；集成层负责外部系统适配。

检查：

- 输入输出模型是否与持久化对象隔离；
- 必填、默认值、枚举、长度、分页、排序、时间、金额和错误码；
- 旧调用方、旧数据、新旧版本并存和灰度兼容；
- 接口重试、幂等 Key、部分成功与最终成功边界；
- 业务规则是否散落在 Handler、Controller、Router、ORM Hook 或工具函数。

简单项目不为形式强行引入复杂分层；复杂业务也不得把所有职责压进单个入口或全局工具模块。

## 三、认证、权限与安全

认证、接口权限、数据权限、租户隔离和状态规则必须在服务端执行。主动检查水平/垂直越权、注入、SSRF、路径穿越、文件上传、反序列化、模板和命令执行、开放重定向、敏感日志以及依赖供应链。

客户端按钮、路由守卫、字段禁用和隐藏只能改善体验，不能替代服务端校验。外部输入进入 SQL、命令、模板、文件路径、URL、反序列化或工具调用前必须经过对应约束和白名单。

## 四、事务、一致性和外部副作用

应用事务只包围必要的数据库操作。检查代理或上下文是否生效、提交与回滚、异常传播、超时、隔离、锁范围、多数据源和重入。

数据库事务不能覆盖 Redis、MQ、HTTP、对象存储、文件或模型调用。跨系统成功边界应根据风险选择 Outbox、幂等、补偿、对账、事务后回调或显式最终一致性，不得用长事务等待外部系统。

## 五、并发、任务和恢复

区分同步 I/O、异步 I/O、CPU 密集、GPU 密集和混合负载。所有线程池、协程集合、进程池、队列、缓存和本地任务集合都应有容量、超时、取消、异常收敛、监控和关闭策略。

可靠长任务不能只依赖进程内后台执行。检查：

- 多实例重复执行、幂等、租约、锁和任务重叠；
- ACK、重试分类、退避、死信、补偿和人工恢复；
- 业务任务 ID、状态、阶段、进度、输入输出引用和失败原因；
- 取消传播、超时、部分失败、进程崩溃和重启恢复；
- 进程内状态在多 Worker 环境中的隔离与内存倍增。

## 六、资源、集成和流式链路

数据库连接、HTTP 客户端、文件流、临时文件、锁、订阅、SSE/WebSocket 和外部 SDK 必须可靠释放。不得每次请求新建高成本客户端，不得无超时调用、盲目重试非幂等操作或记录完整敏感请求响应。

文件处理检查大小、编码、流式读取、路径安全、覆盖风险、中断和临时文件清理；SSE/WebSocket 检查心跳、断开、重连、顺序、重复、落库、会话恢复、多实例路由和资源泄漏。

## 七、质量、性能与验证

根据项目实际体系选择单元、接口、集成、契约、并发、任务和端到端测试。修改后至少执行能直接证明行为的定向验证，并覆盖适用的正常、空值、边界、权限、异常、重复、并发、超时、取消和恢复。

性能判断应基于 SQL、连接、锁、队列、线程/协程、序列化、网络、文件、日志和下游容量证据。不能只靠增加池、并发、实例或内存掩盖根因，也不能没有基线就宣称性能提升。
