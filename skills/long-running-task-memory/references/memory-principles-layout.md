# 外部记忆原则、目录与文档职责

## 本文件目录

- 一、设计原则
- 二、目录约定
- 三、文档职责与写入模式

## 一、设计原则

### 1.1 外部记忆优先

对话上下文、模型内部记忆和压缩摘要只作为当前小节点的临时工作缓存，不作为长期任务状态的唯一来源。

长期任务的目标、授权、进度、证据、决策、阻塞和下一步必须持续写入本机外部记忆，使上下文压缩、会话中断、模型切换或 Agent 切换后仍能恢复。

### 1.2 最小丢失窗口

理想恢复边界：

> 上下文突然压缩或中断时，最多丢失当前尚未完成、尚未形成检查点的一个小节点；此前已经完成的节点必须已经持久化。

因此：

```text
MAX_UNPERSISTED_COMPLETED_NODES = 0
```

已完成的小节点不得只存在于当前对话中。

### 1.3 两类真相

#### 任务控制真相

由当前任务指令和外部记忆维护：

- 目标和非目标；
- 允许和禁止范围；
- 授权边界；
- 阶段和节点；
- 已完成、阻塞和下一步。

#### 技术事实真相

由实际状态决定：

- 当前代码和配置；
- Git 分支、HEAD、工作区和差异；
- 数据库、中间件和文件状态；
- 构建、测试、日志、监控和运行结果。

外部文档决定“计划如何继续”，不能覆盖“系统当前实际上是什么”。

### 1.4 内置 Memories 只是辅助

即使启用了 Codex Memories、Chronicle 或其他自动记忆，也不得将其作为任务硬规则、实时进度或交付证据的唯一来源。自动记忆可能延迟生成、遗漏活跃会话或只提供摘要；确定性的当前状态仍由本机制维护。

## 二、目录约定

根目录使用可配置占位符：

```text
<AGENT_CONTEXT_ROOT>/<项目标识>/
```

推荐结构：

```text
<AGENT_CONTEXT_ROOT>/<项目标识>/
├── PROJECT_CONTEXT.md
├── CURRENT_TASK.md
├── PLAN.md
├── PROGRESS.md
├── DECISIONS.md
├── HANDOFF.md
├── KNOWN_ISSUES.md
├── DELIVERY_RECORD.md
├── reviews/
│   └── <任务标识>/
│       ├── round-01/
│       ├── round-02/
│       └── round-03/
└── archive/
    └── <任务标识>/
```

`<AGENT_CONTEXT_ROOT>` 由当前机器、Codex Home、项目配置或请求方明确指定，不在全局规则中写死使用方名、Windows/WSL/Linux 路径或具体项目。

已有职责相同的本机文档应优先复用，不重复创建同义文件。

## 三、文档职责与写入模式

| 文档 | 作用 | 写入模式 | 更新触发 |
|---|---|---|---|
| `PROJECT_CONTEXT.md` | 长期稳定项目事实、技术栈和硬约束 | 低频修订 | 新的长期事实确认 |
| `CURRENT_TASK.md` | 当前任务最新快照 | 覆盖式 | 每个检查点 |
| `PLAN.md` | 阶段、依赖、风险、验证和复审计划 | 状态修订 | 计划变化、阶段变化 |
| `PROGRESS.md` | 按时间追加的检查点与证据索引 | 追加式 | 每个检查点 |
| `DECISIONS.md` | 重要架构、兼容和业务决策 | 追加式 | 关键决策 |
| `HANDOFF.md` | 暂停、压缩、切换后的最小恢复快照 | 覆盖式 | 交接或暂停 |
| `KNOWN_ISSUES.md` | 当前范围外问题 | 状态修订 | 发现或解决范围外问题 |
| `DELIVERY_RECORD.md` | 已形成实际交付的任务记录 | 追加式 | 形成交付 |
| `reviews/` | 子 Reviewer 原始结构化结果 | 独立文件 | 多 Agent 复审 |

### 3.1 热文档

每次恢复优先完整读取：

- `CURRENT_TASK.md`；
- `PLAN.md` 的当前阶段；
- `PROGRESS.md` 最近 3 个检查点。

### 3.2 温文档

按引用读取：

- `DECISIONS.md` 相关 ADR；
- `reviews/` 对应轮次报告；
- `KNOWN_ISSUES.md` 相关问题。

### 3.3 冷归档

当 `PROGRESS.md` 活跃检查点超过 20 条时，按任务和区间归档旧记录：

```text
archive/<任务标识>/PROGRESS-CP001-CP020.md
```

活跃 `PROGRESS.md` 只保留索引和最近检查点。不得每次恢复都重新加载完整历史。
