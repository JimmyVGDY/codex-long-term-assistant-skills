## 十三、与项目仓库严格隔离

外部记忆：

- 只能保存于 Agent 专用目录；
- 不得放入项目仓库；
- 不得加入暂存、提交和推送；
- 不得写入项目 CHANGELOG；
- 不得通过放入仓库再加 `.gitignore` 规避；
- 不得作为团队正式工程文档交付。

| 类型 | 保存位置 | 是否进入 Git | 作用 |
|---|---|---:|---|
| 项目 CHANGELOG | 项目仓库 | 是 | 正式功能和版本变更 |
| 架构、接口、部署文档 | 项目既有目录 | 按规范 | 团队工程文档 |
| Agent 外部记忆 | Agent 专用目录 | 否 | 恢复、计划、进度和复审 |
| DELIVERY_RECORD | Agent 专用目录 | 否 | Agent 任务级交付记录 |

提交前必须检查外部记忆未误入 Git。

## 十四、内容精简与安全

优先保留：

- 目标、范围和授权；
- 已确认事实和证据等级；
- 修改文件和关键符号；
- 实际命令和验证摘要；
- 复审、问题台账和决策；
- 当前阻塞、风险和下一步。

避免：

- 完整对话和内部推理；
- 大段源码、完整日志和无关工具输出；
- 重复描述；
- 失效猜测和主观结论；
- 密码、Token、密钥、Cookie、隐私和企业敏感信息。

文档中可引用日志、测试报告和 Reviewer 报告路径，不复制全部内容。

## 十五、外部记忆安全与生命周期治理

### 15.1 最小敏感信息原则

外部记忆只记录恢复任务所需的最小事实和证据索引。禁止直接写入：

- 明文密码、Token、Cookie、AccessKey、SecretKey 和私钥；
- 完整数据库、Redis、MQ、对象存储和生产连接字符串；
- 完整身份证、手机号、银行卡、地址和用户隐私；
- 大段原始生产日志、完整请求体、响应体、模型输入输出和消息体；
- 无必要的内部域名、IP、账号和目录拓扑。

需要关联时使用稳定脱敏标识，例如 `<TOKEN_REDACTED>`、`user-***1234`，并在文档中只保存证据文件路径、时间窗和最小摘要。

### 15.2 权限与本地隔离

- Linux/WSL 的 `<AGENT_CONTEXT_ROOT>` 建议使用目录权限 `700`，文档和 JSON 状态文件使用 `600`；
- Windows 应检查 ACL，确保普通其他用户不能读取；
- 不在共享临时目录、项目仓库、容器镜像层和公共网络盘保存外部记忆；
- 不默认把外部记忆同步到 OneDrive、NAS、个人云盘或跨设备工具；如需同步，必须符合公司数据分级和加密策略；
- Reviewer 和子 Agent 不获得共享记忆写权限。

可使用：

```text
checkpoint.py security-check
checkpoint.py secure
```

`security-check` 只能识别常见凭据模式，不能替代人工脱敏和企业 DLP。Windows ACL 不能由该脚本可靠统一配置，必须由本机策略验证。

### 15.3 保留期限

默认建议值：

```text
DEFAULT_COMPLETED_TASK_RETENTION_DAYS = 90
DEFAULT_TEMPORARY_ANALYSIS_RETENTION_DAYS = 30
```

项目、公司和法规要求更严格时，以更严格规则为准。含生产故障、隐私或安全事件的记录不得套用通用期限，必须按组织策略处理。

`retention-report` 只列出超过期限的归档候选，不自动删除。删除、迁移、压缩和备份都属于独立授权动作。

### 15.4 生命周期状态

每个任务归档时应标记：

- 活跃；
- 已完成待观察；
- 已完成可归档；
- 已回滚；
- 已取消；
- 到期候选；
- 法规或审计保留。

不得因达到默认天数就删除仍被项目、审计、事故复盘或法律保留要求引用的记录。

## 十六、归档

任务完成后：

- `PROJECT_CONTEXT.md` 保留长期有效事实；
- `DECISIONS.md` 保留有效决策；
- `DELIVERY_RECORD.md` 持续维护；
- `CURRENT_TASK.md` 清空、切换或归档；
- `PLAN.md`、`PROGRESS.md`、`HANDOFF.md` 和 `reviews/` 归档到：

```text
archive/<任务标识>/
```

- `KNOWN_ISSUES.md` 已解决项更新状态，不静默删除；
- `HANDOFF.md` 标记任务结束，避免误认为当前状态。

未经授权不得删除用户原有本机文档。

---

## 十七、文档维护不等于任务完成

以下不能单独证明任务完成：

- 更新 `CURRENT_TASK` 或 `PROGRESS`；
- 把计划改成已完成；
- 创建 `HANDOFF`；
- 文档宣称测试或复审通过；
- `CHANGELOG` 写明已修复；
- Codex Memories 中存在摘要。

完成仍以实际代码、构建、定向测试、复审、运行结果、Git 状态和验收证据为准。
