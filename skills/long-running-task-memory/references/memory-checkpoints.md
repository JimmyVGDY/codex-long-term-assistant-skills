## 四、启用条件与最小文档集

出现以下任一情况时启用：

- 跨多个会话或多个工作日；
- 三个及以上实施阶段；
- 多模块、服务、仓库或工作树；
- 数据迁移、历史兼容或重大架构调整；
- 生产、灰度、回滚和观察期；
- 大量测试、多 Agent 复审或性能验证；
- 当前上下文较长或预计会压缩；
- 用户明确要求每个节点持续记录；
- 中断后必须准确继续。

启用后最小文档集：

```text
CURRENT_TASK.md
PROGRESS.md
```

多步骤任务增加：

```text
PLAN.md
```

其余文档按事件创建，不机械创建全部模板。

通常不启用：

- 单方法小修复且当前会话可完成；
- 简单说明或一次性命令查询；
- 小范围静态分析；
- 无代码修改的简短问答；
- 纯提交拆分和提交信息修正。

用户明确要求持续检查点时，即使任务看似较小，也应遵循用户要求。

## 五、可独立恢复的小节点

### 5.1 定义

“小节点”是具有明确输入、操作、输出、证据和下一步，并可作为独立恢复位置的最小工作单元。

### 5.2 必须形成检查点的节点

- 完成一个模块、调用链或数据流的阅读并形成明确结论；
- 确认根因或排除一个重要候选原因；
- 完成一组同一功能边界的代码修改；
- 完成一次构建、定向测试、最小复现或导出样例验证；
- 完成数据库迁移或数据修复脚本的设计、执行或验证；
- 启动一轮多 Agent 复审；
- 收齐并归并一轮 Reviewer 结果；
- 形成最小完整修复集合；
- 完成一批集中修复；
- 形成关键技术或业务决策；
- 出现新的阻塞、失败、范围或授权变化；
- 创建提交、推送、部署、重启或完成环境验证；
- 准备等待用户确认、暂停或结束当前会话。

### 5.3 通常不单独形成检查点

- 单次 `ls`、`grep`、`find` 或查看一个短片段；
- 尚未形成结论的临时阅读；
- 修改一个标点或立即撤销的尝试；
- 无状态变化的重复检查；
- 子 Agent 的中间思考过程。

### 5.4 防止长时间无检查点

尚未完成一个完整小节点，但连续执行 5 个实质性动作时，必须写“进行中检查点”。

实质性动作包括：

- 修改代码或配置；
- 执行构建或测试；
- 运行会改变本地状态的脚本；
- 形成影响实现的结论；
- 派发或收集子 Agent；
- 处理数据库、缓存、消息、文件或环境；
- 改变计划、范围或授权判断。

```text
MAX_SUBSTANTIVE_ACTIONS_WITHOUT_CHECKPOINT = 5
```

## 六、检查点事务

每个检查点按以下顺序执行：

1. 重新读取 `CURRENT_TASK.md` 和 `PROGRESS.md` 尾部，避免覆盖其他更新；
2. 生成唯一检查点 ID，例如 `CP-20260729-001`；
3. 确认本节点实际完成内容和证据；
4. 先向 `PROGRESS.md` 追加检查点；
5. 再刷新 `CURRENT_TASK.md` 最新快照；
6. 验证两个文档的最后检查点 ID 一致；
7. 文档写入成功后再继续下一节点。

### 6.1 检查点内容

至少记录：

- 检查点 ID、时间和时区；
- 任务、阶段、节点类型和执行 Agent；
- 本节点目标；
- 实际完成内容；
- 已确认事实和证据等级；
- 修改文件和关键符号；
- 实际命令和结果摘要；
- 验证、复审和环境状态；
- 失败、阻塞、风险和未验证项；
- 对计划和范围的影响；
- 下一步唯一行动。

### 6.2 下一步必须可执行

禁止：

```text
继续优化
继续处理
继续测试
```

应写成：

```text
重新读取 OrderService.updateStatus() 及三个调用方，
确认新增幂等校验是否影响历史状态回写，并执行对应 Service 定向测试。
```

### 6.3 原子写入

工具允许时：

- 更新 `CURRENT_TASK.md` 使用临时文件后原子替换；
- `PROGRESS.md` 追加后刷新并确认写入；
- 写入失败不得假装检查点已完成。

可使用 `scripts/checkpoint.py` 辅助维护。脚本提供 `init`、`append`、`validate`、`recover`、`repair` 和 `archive`；共享写入时使用锁文件防止多个写入者并发覆盖，崩溃后只有确认不存在其他写入者时才允许清理遗留锁。脚本不可用时手工维护同等信息。

## 七、CURRENT_TASK 当前快照

`CURRENT_TASK.md` 必须保持短小、最新、可直接恢复，建议控制在 250 行以内。

至少包含：

- 状态版本；
- 最后检查点 ID 和更新时间；
- 项目、任务、分支、基线和当前 HEAD；
- 工作区差异摘要和未跟踪文件；
- 当前目标、非目标、范围和授权；
- 当前阶段和当前节点；
- 最近完成节点；
- 当前阻塞和未验证项；
- 多 Agent 复审轮次、深度和预算；
- 下一步唯一行动；
- 恢复前必须核对的实际状态。

不得把完整日志、长报告和历史流水堆入 `CURRENT_TASK.md`。

## 八、高风险操作的写前与写后检查点

适用：

- 生产写操作；
- 数据库 DDL / DML 和数据修复；
- Redis、MQ、对象存储和文件删除或迁移；
- Git 提交、推送、强制操作；
- 部署、重启、扩缩容和切流；
- 大范围自动改写；
- 多 Agent 复审启动；
- 任何不可逆或可能部分成功的操作。

### 8.1 操作前检查点

记录：

- 准备执行的动作；
- 目标环境、服务、实例、文件或数据范围；
- 当前状态和授权；
- 预计影响；
- 备份和回滚；
- 验收和停止条件；
- 操作尚未开始。

### 8.2 操作后检查点

记录：

- 实际执行的命令或动作；
- 成功、失败或部分成功；
- 实际影响范围；
- 是否回滚；
- 当前真实状态；
- 下一步验证。

如果上下文在操作中断，恢复 Agent 应能判断操作是未开始、进行中、部分完成、完成还是已回滚。
