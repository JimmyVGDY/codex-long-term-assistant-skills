# 组件与模块复用

用于新增功能、修复、重构和共享实现改动。只读解释和无行为变化排版不触发。目标是正确使用已有能力并保持旧用途稳定，不以复用率或抽象数量衡量完成度。

## 一、先定位，再判断

修改前执行：定位已有能力 → 阅读实现和使用方 → 判断适用性 → 选择方案 → 验证新旧行为。

项目已有能力索引，或属于首次非简单项目接管时，按[能力索引开发流程](capability-index-workflow.md)执行查询/有界初扫、源码核实和变更后维护。读取该流程不需激活额外Skill。无索引的简单修复直接做有界源码检索。

- 从目标模块、相邻模块、公共目录及现有文档开始，按功能语义、类似流程、符号、导出入口和实际调用方检索；不能仅凭名字或目录判断不存在可用实现。
- 阅读候选实现、代表性使用方、相关测试和示例，确认配置、依赖版本、运行环境和弃用状态。索引只是线索，过期或冲突时回到源码；不要为一次局部修改建立全仓库索引。
- 只有证据不足时才沿依赖和调用链扩大范围；简单任务完成局部检查即可，不机械全仓扫描。
- 区分“检索范围内未发现”“发现但不适用”“尚未完成检查”。最后一种不能作为新建理由；先补足与决策有关的检查，客观无法读取时明确未知项与影响，不冒充已排除。

## 二、选择最小充分方案

判断职责与业务语义、输入输出、错误语义、状态与副作用、权限/租户、资源生命周期、依赖和运行边界是否匹配。

| 决策 | 条件 | 最少证据 |
|---|---|---|
| 直接复用 | 已有实现适用 | 文件/符号、使用位置或调用示例 |
| 扩展已有实现 | 同一职责，可兼容增加能力 | 扩展点、原默认行为、受影响使用方 |
| 抽取公共模块 | 多处语义一致且共同维护有明确收益 | 共同规则、差异边界、迁移范围 |
| 独立新建 | 范围内无适用实现，或复用增加风险 | 已检查范围、候选不适用原因（如有）、新职责 |

局部修复也可以保留现有实现，不需要为四类决策人为新增工作。代码形似不代表业务语义相同；不得为复用跨越权限、数据所有权或生命周期边界。避免通过大量业务开关制造万能组件、透传包装或全局工具模块。允许有依据的独立实现，不顺手重构无关重复代码，不自动抽取跨项目公共库。

### 维护成本判断

先满足语义、权限、契约、状态和生命周期约束，再比较实际可行方案的长期成本：

| 维度 | 主要判断 |
|---|---|
| 变化耦合与归属 | 使用方是否独立演进；共同规则由哪个模块负责 |
| 接口与依赖 | 是否增加业务开关、隐含顺序、透传层、循环依赖或版本锁定 |
| 理解与排查 | 规则位置、调用链和错误定位是否更清楚 |
| 影响与验证 | 会影响哪些旧用途，需要哪些直接测试；不靠大量Mock掩盖边界 |
| 迁移与恢复 | 调用方迁移、版本共存和回退是否可控 |
| 运行资源 | 是否引入额外I/O、连接、内存、缓存或并发耦合 |

普通任务简述主要权衡；跨模块或有争议时比较2—3个真实可行方案，区分证据、推断和未知。无必要不读取完整Git历史，不设置机械总分，不为形式创造替代方案。减少代码行数、条目数增加或复用率提高都不能单独证明维护收益。

## 三、保持旧用途稳定

- 根据公开导出和调用链识别受影响使用方；动态注册、插件和仓库外消费者无法完整确认时记录范围限制，不宣称全部覆盖。
- 未明确指定改变时，保留旧参数、默认值、返回值、错误行为及副作用；新增能力优先保持默认行为兼容。
- 修改共享实现前先检查现有契约/特征测试；有风险的旧行为存在缺口时，优先补充能证明该行为的测试。不要为低风险、可逆修改编写只镜像实现的测试。
- 修改后验证新用途和受影响旧用途，按实际风险覆盖权限、异常、状态隔离、取消和资源释放。构建通过或全部 Mock 的测试不能单独证明兼容。
- 抽取或迁移后，清理本次被替代的旧实现，确认调用方实际使用共同规则；不能用同名定义覆盖、不可达旧代码或仅切换部分调用方冒充完成。清理范围仅限本次替代代码。
- 破坏性变化单独说明迁移、版本共存、停止和回滚；没有对应授权时不混入普通复用改动。

## 四、简短证据与复审

在已有任务摘要或审查包中记录“检索范围与候选 → 决策及理由 → 使用方影响 → 验证与未知项”，关联文件/符号或调用链。简单任务一句话即可，不强制新增文档或运行时字段；基线变化时复验受影响判断与证据。

已有索引的相关能力发生变化后，由主协调者在可恢复节点合并失效和更新；沿用现有摘要关联ID、观察范围及主要维护权衡，不复制整份索引。无相关变化不追加记录，索引不自动晋升为稳定记忆。

已有复审被触发时，功能 Reviewer 检查能力遗漏及共同业务语义，兼容 Reviewer 检查旧使用方和共享状态，测试交付 Reviewer 检查新旧用途证据。重复实现 Finding 必须定位可用的已有实现和具体风险；纯抽象偏好不能自动阻塞。此规则不新增固定 Reviewer，也不修改复审预算或授权边界。

## 五、规则效果验证

链接、包校验和本地化只能证明规则可分发，不能证明 Agent 稳定执行。行为回放使用独立初始工作区和仅描述任务目标的输入，保留优化前后规则、模型/强度设置、场景基线及实际结果；期望答案不提供给执行 Agent。分别报告发现、重复实现、错误复用、旧用途回归和额外读取/执行成本，未知保持未知。有限样本通过不能宣称所有项目必然复用成功。
