# 实施后复审与完成定义

## 本文件目录

- 七、实施后独立复审与多 Agent 审查门禁
- 八、完成定义

## 七、实施后独立复审与多 Agent 审查门禁

### 7.1 复审目的

本节只处理实施后门禁。实施前设计审查不能替代稳定 `git diff`、最低定向验证和实施后复审。

复审用于降低修复后产生新 Bug、影响原有功能、改变业务口径、引入权限或安全漏洞、增加性能资源负担以及产生新的状态和边界问题。复审不能替代运行测试。

### 7.2 触发条件

真实修改运行行为的代码或可执行内容时原则上触发，包括后端、前端、公共库、脚本、Worker、调度、数据处理、导出、迁移和逻辑配置。

通常不触发：

- 纯提交拆分或提交信息修正；
- 仅调整 CHANGELOG 排版；
- 只读排查和未修改代码的静态分析；
- 不改变行为的普通文字修正。

生产、权限、资金、数据迁移、核心状态和高并发链路不得无理由豁免。

### 7.3 首选：多 Agent 严格独立门禁

条件允许时组合 `$multi-agent-independent-review`，按风险启动职责不同的 Reviewer；必须区分 system-readonly 与 logical-readonly，对功能与口径、回归与兼容、权限与安全、性能与资源、数据与契约、状态与并发以及测试与交付进行并行审查。

必须遵循：

- Reviewer 只读，不修改、提交、推送、部署、重启或执行生产写操作；
- 第一轮 Reviewer 全部返回前，不边审边零散改代码；
- 主协调 Agent 统一去重、根因聚类、冲突裁决和分级；
- 形成“最小完整修复集合”后集中修复；
- 修复后只复核受影响范围，公共边界变化时扩大范围；
- 默认最大审查深度 3、最大复审轮次 3、最大并行 Reviewer 6、单功能边界最多 12 个 Reviewer、最大集中修复轮次 3；
- 达到上限后停止自动循环，保留阻塞和未验证项，不得伪称通过。

详细流程、Reviewer 角色、输出模板和停止规则由 `$multi-agent-independent-review` 定义。启用 `$long-running-task-memory` 时，复审计划、派发、结果收齐、归并、集中修复、重新验证和最终复核都必须形成检查点；只有主协调 Agent 更新共享记忆。

### 7.4 受限环境兼容门禁

仅在工具客观不支持独立 Reviewer，且任务不属于必须严格门禁时使用：

1. 实施完成后切换到只读复审阶段；
2. 重新读取实际 `git diff`、完整上下文、调用链、契约和测试证据；
3. 不以实施过程中的预期作为结论；
4. 按六维输出问题、证据、等级、阻塞和未验证项；
5. 明确标记“隔离二次复审，不等同于真正独立 Reviewer”；
6. 是否允许提交由当前任务卡或用户授权决定。

禁止把兼容门禁伪称为严格独立复审。

### 7.5 标准顺序

```text
完成功能边界修改
    ↓
执行最低定向验证
    ↓
稳定当前 git diff
    ↓
多 Agent 并行独立复审或受限兼容复审
    ↓
统一归并并形成最小完整修复集合
    ↓
实施者集中修复阻塞问题
    ↓
重新执行受影响验证
    ↓
定向复核受影响范围
    ↓
更新正式文档或 CHANGELOG（按项目规范）
    ↓
检查差异并提交
```

复审后修改相关代码，必须重新验证和复核受影响范围。

### 7.6 六个核心维度

1. 权限与越权；
2. 安全；
3. 功能正确性与业务口径；
4. 原有功能回归与兼容性；
5. 性能与资源负担；
6. 状态、交互与新边界。

测试证据和交付边界作为补充专业维度独立检查。

### 7.7 输出和结论

输出功能边界、差异基线、文件、调用链、Reviewer 和轮次、六维结论、归并问题、等级、根因组、是否阻塞、未验证项、修复轮次和最终结论。

等级：阻塞、高、中、低、建议。

最终结论只能使用：

- 通过，无阻塞项；
- 有非阻塞问题；
- 有阻塞问题；
- 达到复审上限，仍有阻塞或未验证项；
- 工具或环境受限，未完成严格独立复审；
- 不适用。

Reviewer 只报告，实施者修改。阻塞问题解决前不得形成最终交付。

## 八、完成定义

任务只有满足所有适用条件才算完成：

1. 目标问题已处理且未扩大范围；
2. 代码可编译或构建；
3. 最低定向验证已执行；
4. 回归、兼容、安全、性能和用户体验已检查；
5. 无调试代码、临时文件和敏感信息；
6. 正式文档和 CHANGELOG 已按当前项目规范更新；
7. Git 差异已检查，功能边界与提交边界一致；
8. 适用的严格或兼容复审已完成，阻塞项已解决；
9. 已按授权提交、推送、部署、重启或在指定位置停止；
10. 所有失败、未验证和遗留风险已明确说明。

如果任务卡明确要求严格独立复审，而工具无法完成，则任务可以是“代码处理和验证已完成，但最终质量门禁受阻”，不得伪称全部完成。
