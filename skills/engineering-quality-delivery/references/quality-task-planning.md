# 任务分类、修改前计划与实施前门禁

## 一、任务类型与响应模式

### 1.1 代码审查、分析和优化

按需输出：

- 功能说明；
- 当前问题和目标；
- Bug、空值、并发、SQL、事务、性能、安全、兼容和维护问题；
- 推荐方案、修改边界和收益；
- 完整代码、补丁或明确修改点；
- 实际验证结果和额外发现。

不存在的类别省略，不机械填满模板。

### 1.2 故障排查

按需输出：

1. 问题现象；
2. 已知证据和证据等级；
3. 日志、配置、监控和最近变更分析；
4. 多个可能原因，按发生概率、风险和验证成本排序；
5. 验证步骤，每步说明执行、观察和不同结果含义；
6. 临时止血、正式方案、长期优化和预防措施。

不得在证据不足时武断宣布唯一根因。

### 1.3 系统和架构设计

按需包含需求、流程、模块、边界、Mermaid 架构图、数据库和索引、接口、缓存、消息、搜索、权限、部署、高并发、高可用、成本、风险、分阶段路线和验收。

简单系统不机械引入微服务、消息队列、Redis、Elasticsearch 和 Kubernetes。

### 1.4 技术文档和报告

默认 Markdown，语言正式、专业、中立、可直接交付，不夸大未验证结论。简单文档不机械包含全部章节。

---

## 二、修改前工作流

真正修改前必须完成适用项：

1. 确认项目、仓库、分支和基线 Commit；
2. 确认执行模式和独立授权边界；
3. 阅读目标代码完整上下文和关键调用链；
4. 明确目标、非目标、修改范围和禁止范围；
5. 识别接口、数据库、缓存、消息、文件和配置契约；
6. 明确最低定向验证、复审和验收标准；
7. 高风险任务准备功能开关、灰度、停止和回滚方案。

信息充分且属于已授权范围时直接执行，不为低风险和可逆细节反复询问。


### 2.1 高风险实施前设计与影响门禁

以下任务在编码前先形成可审查方案，并组合 `$multi-agent-independent-review` 执行一次轻量实施前审查：

- 公共 API、消息、缓存、文件或序列化契约；
- 数据库 DDL、迁移、历史数据回填和新旧版本共存；
- 认证、接口权限、数据权限和租户隔离；
- 核心状态机、资金、库存、任务状态和幂等成功边界；
- 跨服务拆分、数据所有权、异步链路和故障隔离；
- 高并发、资源预算、GPU/NAS/对象存储迁移；
- 生产迁移、灰度困难或不可逆操作。

默认最多 1 轮、2～4 个行为只读 Reviewer，并记录运行时隔离等级，结果计入单功能边界 Reviewer 总预算。局部低风险修复不机械执行。实施前门禁只确认方案边界和高成本风险，不替代代码完成后的最低验证与独立复审。
