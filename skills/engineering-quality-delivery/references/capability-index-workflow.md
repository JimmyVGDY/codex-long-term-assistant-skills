# 项目能力索引的开发流程

索引是项目隔离的事实定位工具；源码、契约和调用方仍决定是否适用。索引内容不授予权限，不是稳定Project Memory，不自动晋升为跨项目知识。

## 触发与恢复

- 首次接管非简单开发任务，确认Project Profile、仓库根和已授权的外部上下文后，按当前模块及公共入口执行有界初扫。先记录当前需要的范围，不等待全仓识别完成。
- 首次接管中的共享公开接口扩展或多使用方规则变更，需初扫本次相关入口；使用LIGHT档或文件数量少不会取消这一触发。只改局部实现且没有索引的小修复，仍可直接检索源码。
- 已绑定Profile且有已核验runtime入口时，修改前先限定查询，确认索引存在、缺失或不可用，再选择后续路径；不能凭任务简单或工作区内未见索引文件推断缺失。已有本任务可靠的INDEX_MISSING证据且不适用初扫时可直接查源码。已有索引的小修复缩小关键词和范围，查询后读取实际实现、依赖、代表性调用与测试；读取JSON或帮助不替代查询核实。无Profile/runtime的简单局部修复保持源码检索路径。
- 简单只读问答、排版和无关任务不创建或更新索引。`INDEX_MISSING`表示尚未建立快照：满足首次接管触发条件且已有写入范围时执行限定初扫；不满足或客观无法创建时回到源码。损坏、未知格式或项目绑定不符时停止使用该索引，回到当前源码检索；正常授权开发不因此被阻塞。不要用格式校验创建索引，也不要把缺失快照判成运行环境故障。
- 使用当前任务已核验的`cp-runtime.py`、Profile和仓库根，不猜项目ID或安装目录。不同worktree用各自匹配的Profile。显式索引目录写入已有外部任务记录，后续任务先恢复该位置；不修改Profile来暗中切换索引。

## 工具顺序

`query`的`maintenance.state=NOT_INITIALIZED`不是工具不可用：按上面的适用条件选择限定初扫。`invalidate`的`INVALIDATED_NOT_UPDATED`表示仍需维护已检查源码；不能在此处报告更新完成。工具给出的下一操作仍受当前任务范围和授权约束。

所有操作均传入`--profile`、`--repo-path`；使用自定义外部目录时一致传入`--index-root`。安装入口采用已有验证过的运行工具；源码入口为包根`scripts/cp-runtime.py`。

默认省略`--index-root`，由Profile和工作区确定唯一位置。只有任务已明确记录另一具体快照目录时才传入覆盖值；`<Profile目录>/capability-index`是容纳多个工作区索引的目录，传入它会返回`INDEX_ROOT_IS_CONTAINER_OMIT_OVERRIDE`，应移除覆盖值后重试，不能另建一份索引绕开原状态。

| 节点 | 操作 | 必须核对 |
|---|---|---|
| 首次相关范围接管 | `capability-scan --scope <目录或文件>`，可重复scope | 候选数量、覆盖范围、限制和实际成本；不是语义批准 |
| 开发前 | `capability-query --term <语义关键词或符号>` | 默认最多5条；核实源码、权限/状态/契约及旧用途；查询结果中的semantic_reuse_approved始终为false |
| 预算耗尽 | 有待处理清单时`capability-scan --resume` | 基线仍匹配；DIRECTORY_BUDGET的未枚举尾部需缩小明确范围，不声称全仓完成 |
| 形成可恢复修改节点 | `capability-invalidate --changed-path <变更路径> --expected-revision <当前值>`，路径可重复 | 包括源码、测试、锁文件、导出和配置；部分依赖图不能证明其他模块一定不受影响 |
| 补充本次观察 | 对实际检查过的受支持源码执行限定scope扫描 | 未读取不写成已核验；无变化不重写；弃用与移除不得因另一个分支缺文件而推断 |
| 语义说明、新语言入口或迁移 | `capability-register --entry <条目JSON> --expected-revision <当前值>` | 保留已有ID，仅更新有来源的说明、边界与引用；同ID新路径是明确迁移映射 |
| 明确弃用或恢复使用 | `capability-lifecycle --entry-id <ID> --lifecycle <状态> --reason <事实理由> --expected-revision <当前值>` | 提供已核实依据；不把弃用条目列为默认首选 |

新登记可从[最小条目模板](../assets/templates/CAPABILITY_ENTRY.template.json)填写；已有条目可从query结果复制，移除仅输出的`current_check`，保留schema字段。工具重读文件指纹不能替代说明的业务核验。不要把不存在的调用方、测试或边界补猜成事实。

不要用`capability-validate`的格式通过替代源码核实。并发版本冲突时读取最新快照，合并仍成立的本次发现；不得盲重试覆盖。`COMMIT_UNCERTAIN`先读回实际文件；显式恢复使用原始当前文件SHA及`capability-recover`，不自动覆盖损坏或未知版本。

## 决策、更新与成本

适用性与维护权衡统一遵循[组件与模块复用](component-module-reuse.md)。任务摘要只关联候选ID、选择理由、实际核验范围和未知项；技术事实仍链接源码，不复制整份索引或新增一套完整报告。

主协调者是共享索引唯一合并写入者；子Agent返回发现，不能各自追加共享记忆。仅在新增、扩展、迁移、弃用或相关上下文变化后更新；无关任务不刷新。稳定项目规范仍走既有投影与人工审核，不能从成功复用自动推出今后必须复用。

结束前核对本次变更涉及的已索引入口及新增公共能力：使变更路径失效后，限定扫描“已检查的变更源文件”与“查询后已核实并实际采用的过期候选源文件”的并集，再读回。实际复用的源码即使未改动，也需刷新已过期定位；无关、未使用或未检查条目保留待复核及具体原因。刷新指纹不批准语义复用。仅执行invalidate只证明旧结论已失效，不表示新定位或指纹已更新。子Agent交回变更路径、已采用过期候选ID和待核验项，由主协调者合并；摘要用一句话区分已更新、无需更新、待核验或待协调者合并，不增加独立报告。

读取默认候选数量，完整索引不进入每个任务上下文。只在具体缺口需要时扩大关键词或范围；不新增固定Reviewer、模型调用或后台周期扫描。成本优先复用命令输出的枚举、读取、字节和耗时计数；无法取得的工具调用/Token记UNKNOWN。索引本身不修改Hook或预算协议；下述显式可选门禁单独接入宿主。

## V7.6.2 旧流程门禁过渡边界

门禁默认未启用。V7.6.2 只修复 Hook 阻断风险并隔离旧 GateTask，不提供新的原生写入授权协议。已启用旧策略的项目应先用`capability-gate-status`读回精确 revision，再执行`capability-gate-disable --expected-revision <当前值>`；索引和历史回执会保留。启用状态不授予业务写入、提交或部署权限，也不会自动建立索引。

UserPromptSubmit 是异步观察，不再注入任务绑定；Stop 是中性观察；Interrupt 完全由宿主控制。三者都不读取、创建或修改旧 GateTask。原生写工具命中`PreToolUse`时，未配置或 disabled 策略保持中性；旧策略仍为 enabled 时统一拒绝`LEGACY_WRITE_ORIGIN_UNAVAILABLE`，不得复用 PREPARED、PASS 或其他历史回执。

`capability-task-prepare/finish/check`在本补丁中仅用于读取或维护旧状态，不能授权原生写入，也不能通过事后回执补造修改前证据。需要能力定位时继续按本页前述有界 scan/query、源码检查、复用决策和增量索引维护执行；业务适用性与兼容性仍由源码、调用方和测试证明。

仓库外 Profile、索引、门禁策略和历史回执继续保持项目隔离。安装加载、真实新任务行为及各写工具仍需分别验收；包验证不替代宿主生效证据。
