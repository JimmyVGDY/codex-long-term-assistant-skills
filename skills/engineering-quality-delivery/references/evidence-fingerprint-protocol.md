# 验证与复审证据指纹协议

## 目标

防止代码、配置或 Git 差异在测试和复审后继续变化，但 Agent 仍沿用旧的“已通过”结论。

## 指纹组成

- Git HEAD；
- 暂存和未暂存差异；
- 有界未跟踪文件摘要；
- 当前功能边界的相关文件；
- 执行命令、环境和结果文件；
- Reviewer 审查包 hash。

## 状态

- `valid`：当前仓库指纹与记录一致；
- `stale`：代码、配置或差异已变化，旧证据不能继续证明当前版本；
- `failed`：命令实际失败；
- `blocked`：环境或权限不足；
- `unknown`：证据不完整。

## 强制规则

1. 验证和复审记录必须绑定当前仓库指纹。
2. 任何受影响代码、公共契约、迁移或配置变化后，相关证据自动视为 `stale`。
3. 复审后修复代码时，旧 review packet 和受影响测试不能继续标记 `valid`。
4. 全量测试中的历史失败必须单独保留，不能因为指纹一致就忽略。
5. `execution_guard.py validate` 只判断证据与当前状态是否一致，不替代测试本身。
