# 执行档位与阶段状态机

## 一、三档执行模式

| 档位 | 典型任务 | 默认 Skill 与门禁 |
|---|---|---|
| `LIGHT` | 概念解释、一次性只读分析、无行为变化文字调整、极小低风险改动 | 1 个主领域 Skill；不启用长期记忆；不机械启动多 Agent；只执行与实际改动匹配的最小验证 |
| `STANDARD` | 普通 Bug 修复、接口/页面调整、脚本或配置行为变化 | 1 个主领域 Skill + 质量交付；执行最低定向验证；按风险选择 0～2 个 Reviewer；必要时建立简化任务信封 |
| `STRICT` | 生产、真实数据、权限安全、资金库存、不可逆迁移、核心状态机、跨服务高风险改造 | 长期记忆、完整任务信封、实施前审查、最低验证、实施后独立复审、回滚与停止条件；严格只读场景需提供实际隔离证据 |

### 升级和降级

- 发现真实数据、不可逆变化、公共契约、跨服务、权限或高资源风险时，必须升级档位。
- 已进入 `STRICT` 后，不得仅为了节省时间自动降级；降级必须记录理由、明确授权和仍保留的风险。
- 安装了多 Agent 或长期记忆能力，不代表每个任务都必须使用。

## 二、阶段状态机

标准阶段：

```text
IDENTIFY → PLAN → IMPLEMENT → VALIDATE → REVIEW → DELIVER → CLOSED
```

辅助状态：`BLOCKED`、`CANCELLED`、`ROLLBACK`、`RECOVER`。

### 阶段职责

- `IDENTIFY`：识别项目、事实、目标、权限和风险；禁止直接扩大到修改。
- `PLAN`：明确范围、非目标、方案、门禁、回滚和 Skill 激活计划。
- `IMPLEMENT`：只做当前功能边界修改；Reviewer 不在本阶段修改代码。
- `VALIDATE`：执行构建、定向测试、样例、迁移或运行验证并记录指纹。
- `REVIEW`：独立上下文 Reviewer 基于统一审查包工作；本轮结果收齐前不修改。
- `DELIVER`：检查 Git、文档、授权、提交/推送/部署/重启和生效状态。
- `RECOVER`：上下文压缩或会话切换后核对信封、检查点、Git 和证据有效性。

### 转换门禁

- `PLAN → IMPLEMENT`：目标、范围、授权和停止条件明确；STRICT 已完成实施前门禁。
- `IMPLEMENT → VALIDATE`：差异稳定，无明显无关改动。
- `VALIDATE → REVIEW`：最低验证有真实证据；失败和未验证项已记录。
- `REVIEW → DELIVER`：阻塞问题解决，受影响证据未失效。
- 任意阶段发现范围扩张、权限不足、生产风险或证据失效，可进入 `BLOCKED` 或退回前一阶段。
