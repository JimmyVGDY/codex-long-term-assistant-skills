# 搜索、向量、文件存储与实时链路

## 五、Elasticsearch、搜索和向量数据库

### 5.1 Elasticsearch

检查：

- Mapping、字段类型、分词器和动态映射；
- Keyword / Text、日期、数值和嵌套对象；
- 分片、副本、刷新、段合并和磁盘水位；
- 查询 DSL、深分页、聚合、排序和脚本；
- 索引模板、别名、ILM 和滚动索引；
- 批量写入、版本冲突和重试；
- 权限、敏感字段和多租户隔离。

避免无边界通配符、前导通配符、超大 `size`、深度 `from + size` 和高基数聚合。深分页评估 `search_after` 或 Scroll 的适用边界。

索引重建优先新索引 + 别名切换，保留回滚别名。删除索引属于高风险操作。

### 5.2 向量数据库

检查向量维度、距离算法、索引类型、过滤条件、多租户、批量写入、删除、重建、版本和成本。

Embedding 模型变化通常意味着向量不可直接兼容，需要版本化索引和重建方案。

## 六、文件、NAS、对象存储和 CDN

主动考虑：

- 文件一致性、元数据状态和数据所有权；
- 对象 Key、上传幂等、重复文件和校验；
- 分片、断点、限速、超时、失败重试和取消；
- 全量迁移、增量同步、灰度切读写和回滚；
- CDN 缓存、刷新、版本 URL 和旧资源兼容；
- NAS 重 I/O、大目录遍历、大文件和小文件问题；
- 线程池、进程和 Worker 隔离；
- 临时文件、磁盘空间、清理和存储成本。

### 6.1 一致性模型

必须明确：

- 数据库元数据与文件对象谁是事实源；
- 上传成功、元数据提交和消息发送的顺序；
- 部分成功和失败补偿；
- 删除是软删除、延迟删除还是立即删除；
- 同步任务如何幂等和断点恢复。

### 6.2 安全

检查路径穿越、越权下载、签名 URL、MIME、扩展名、文件签名、恶意文件、目录逃逸和对象 Key 注入。

不得信任用户文件名作为物理路径。生产删除对象和目录必须先确认范围和恢复能力。

### 6.3 NAS 资源控制

大目录遍历、索引刷新、递归删除和批量校验属于重 I/O。应通过任务队列、并发上限、优先级和速率控制保护共享存储，但不能简单把所有普通读取串行化。

## 七、SSE、WebSocket 和流式链路

跨前后端检查：

- 连接建立、心跳、超时、关闭和重连；
- 客户端断开、服务端取消和下游任务取消；
- 消息顺序、重复、半截消息和最后事件位置；
- 数据落库、上下文保存和刷新恢复；
- 多实例路由、粘性会话、广播和网关缓冲；
- 页面切换、浏览器休眠和资源释放；
- 任务状态与展示状态最终一致。

不得只修复连接表现而忽略消息落库、上下文、任务状态、泄漏和恢复。
