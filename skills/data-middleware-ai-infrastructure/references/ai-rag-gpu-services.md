# AI、RAG、GPU 与服务拆分

## 八、AI、RAG、模型和 GPU

### 8.1 AI 调用

主动分析：

- 模型能力和使用边界；
- Prompt、System Prompt、上下文窗口和 Token 成本；
- JSON Schema、结构化输出、校验和修复；
- Prompt 注入、敏感信息和工具权限；
- 超时、重试、降级、多模型路由和缓存；
- 幂等、取消、失败恢复和链路追踪。

不得把模型输出直接视为可信业务数据。涉及金额、权限、状态和执行命令时必须程序化校验。

### 8.2 RAG

检查：

- 文档解析、Chunk 大小、重叠和 Metadata；
- Embedding 模型、向量维度和版本；
- TopK、BM25、混合检索、RRF、Rerank 和 MMR；
- 权限过滤、多租户和敏感文档；
- 数据更新、删除、重建和索引一致性；
- 评测集、召回、准确性、幻觉和引用。

RAG 评测不能只看主观示例，应建立真实问题、期望证据和可重复指标。

### 8.3 Agent 和工具调用

明确工具权限、输入 Schema、超时、幂等、重试、人工确认和审计。工具返回必须校验，不得让模型自由拼接高风险命令或 SQL 并直接执行。

### 8.4 GPU 和视频任务

检查显存、模型常驻、同卡竞争、Worker 并发、队列、优先级、OOM、批处理、取消、恢复、Worker 崩溃、中间产物、文件清理和 GPU 利用率。

GPU 任务需要资源预算和调度策略，不能只通过增加并发提升吞吐。必须同时评估 CPU、内存、磁盘、网络和模型加载开销。

## 九、微服务和服务拆分

不得因为性能问题直接建议拆微服务。先定位 SQL、缓存、阻塞、连接池、线程池、单进程限制、文件 I/O、CPU、GPU、外部接口和任务异步化。

拆分依据：

- 业务、数据和事务边界；
- 发布独立性和故障隔离；
- 资源类型和扩缩容；
- 团队组织、运维成本和网络开销；
- 数据一致性和可观测性成本。

早期和小型项目优先模块化单体 + 独立 Worker。常见合理拆分包括 Web API、普通 Worker、文件 Worker、视频 Worker、AI Worker、GPU Worker 和调度服务。

服务间必须统一 traceId、错误码、超时、重试、幂等和版本策略，避免循环依赖和多层重试。
