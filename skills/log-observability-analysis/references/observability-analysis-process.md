# 统一时间线、聚类、关联和根因验证流程

## 本文件目录

- 五、标准分析流程

## 五、标准分析流程

### 4.1 输入盘点

形成日志清单：

| 来源 | 环境 | 服务/实例 | 时间范围 | 时区 | 格式 | 大小 | 完整性 | 敏感性 |
|---|---|---|---|---|---|---:|---|---|

识别：

- 日志轮转、缺失、采样、截断和乱序；
- 多行堆栈和异步日志交错；
- 相同事件被多层重复记录；
- 时钟漂移和时区不一致；
- DEBUG/INFO/WARN/ERROR 的语义是否可靠；
- 是否存在日志洪泛或关键日志缺失。

### 4.2 统一时间与关联字段

- 将所有时间统一到明确时区；
- 保留原始时间和标准化时间；
- 识别毫秒、秒、纳秒等精度差异；
- 通过 traceId、requestId、taskId、messageId、账户/业务标识、线程、进程、Pod 和实例关联；
- 无关联 ID 时，使用时间、接口、对象 ID、错误码和上下游事件构建弱关联，并标注证据强度。

### 4.3 初筛与聚类

至少检查：

- 首次异常和最后一次异常；
- 错误峰值、持续时间和恢复点；
- 异常类型、错误码、堆栈指纹和消息模板；
- 超时、重试、熔断、降级、取消和补偿；
- 连接池、线程池、队列、锁、GC、OOM、磁盘和网络；
- 业务状态变化、部分成功和重复处理；
- 同一根因引发的多种表象；
- 异常发生前后的配置、发布、流量和依赖变化。

不要只统计 `ERROR`。很多根因可能出现在 WARN、耗时、连接等待、重试或状态日志中。

### 4.4 建立时间线

时间线至少包含：

- 时间；
- 服务/实例；
- 事件；
- 关联 ID；
- 证据位置；
- 证据等级；
- 对故障链路的意义。

优先确定：

1. 正常基线；
2. 触发事件；
3. 第一个异常信号；
4. 故障扩散；
5. 重试/降级/恢复；
6. 业务影响；
7. 最终恢复或持续异常。

### 4.5 跨来源关联

复杂任务可按来源或维度并行分析：

- 应用与业务日志；
- 数据库、连接池和事务；
- Redis、MQ、ES；
- 容器、K8s、系统资源和网络；
- 安全和访问日志；
- 时间线与根因归并。

子 Agent 必须只读并返回结构化结果。主 Agent 负责：

- 统一时区和范围；
- 去重相同事件；
- 处理冲突结论；
- 区分同因多果与多个独立故障；
- 形成统一证据台账。

普通单文件、单服务问题不应为了形式多开 Agent。

### 4.6 根因假设与证据分级

每个候选原因记录：

| 候选原因 | 支持证据 | 反证/缺口 | 证据等级 | 验证步骤 | 验证风险 |
|---|---|---|---|---|---|

证据等级：

- **已确认**：日志和其他状态形成直接闭环，或已稳定复现；
- **高概率**：多项证据一致，但缺少关键验证；
- **推测**：工程上可能，但直接证据不足；
- **未验证**：当前日志或权限不足。

禁止：

- 把时间先后直接写成因果；
- 因看到异常堆栈就认定它是最初根因；
- 忽略重试、包装异常和下游错误导致的表象；
- 根据单个样本外推所有请求；
- 因日志中没有记录就断言事件没有发生；
- 在时区未统一时拼接跨服务时间线。

### 4.7 设计验证步骤

每一步必须说明：

- 执行什么；
- 环境和范围；
- 观察什么；
- 不同结果分别说明什么；
- 是否只读；
- 性能和安全风险；
- 停止条件。

优先使用低成本、低风险、可回退的验证。生产环境无法安全验证时，明确标为未验证，并建议在预发布、镜像数据或本地复现中完成。
