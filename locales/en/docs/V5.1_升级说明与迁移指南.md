# Codex Cross-Project Long-Term Engineering Assistant V5.1 Upgrade Notes and Migration Guide

## 1. Release Positioning

V5.1 extends V5.0 project governance and evidence closure with this controlled self-evolution path:

```text
Execution Feedback / Review / Evidence / Checkpoint / Audit
                  ->
            Self Observation
                  ->
     Value and Complexity Analysis
                  ->
        Optimization Proposal
                  ->
        Human Accept / Reject / Defer
                  ->
       Independent Implementation Task and Explicit Approval
```

Self-evolution is strictly limited to observation, analysis, proposals, and records of human decisions. It neither has nor simulates permission to:

- modify Skills, Reviewers, model tiers, or global configuration automatically;
- accept its own proposal automatically;
- create commits, push, deploy, restart, or write production automatically;
- promote one project's experience into a cross-project global rule automatically;
- substitute Evidence, a Proposal, or ACCEPTED state for a Task Envelope and Approval.

Every Proposal keeps `execution_authorization=NONE`.

## 2. Compatibility

V5.1 retains V5.0's nine Skills, seven Reviewers, project-governance runtime, Task Envelope V2, Approval, Evidence, Checkpoints, Memory Projection, and Finalization Integrity.

New capability has one authoritative location:

```text
runtime/cp_runtime/evolution/
```

New CLI:

```text
Package directory: scripts/evolution.py
After installation: ${CODEX_HOME}/tools/evolution.py
```

V5.0 project contexts remain reusable:

```text
~/.codex/project-context/<project-id>/
```

V5.1 adds only:

```text
evolution/
├── snapshots/
├── assessments/
├── proposals.jsonl
└── decisions.jsonl
```

It does not write state into business repositories by default.

## 3. Upgrade Steps

1. Back up current `~/.codex` configuration and V5.0 installation.
2. Install V5.1 with the package's existing installer.
3. Run existing `verify` and `doctor`.
4. Run the V5.1 specialist validation:

```bash
python3 -B scripts/validate-v51-evolution.py
```

5. Run a read-only observation for an onboarded project:

```bash
python3 -B scripts/evolution.py observe \
  --project-id <project-id> \
  --context-root ~/.codex/project-context
```

6. After verifying sources and snapshot content, generate proposals:

```bash
python3 -B scripts/evolution.py run \
  --project-id <project-id> \
  --context-root ~/.codex/project-context
```

## 4. First-Use Recommendation

Use an explicit source initially to avoid unstandardized JSONL in historical directories:

```bash
python3 -B scripts/evolution.py run \
  --project-id <project-id> \
  --context-root ~/.codex/project-context \
  --source feedback/execution-feedback.jsonl \
  --dry-run
```

`--dry-run` outputs observations, assessments, and proposal candidates without writing registries. Remove it only after confirmation; then snapshots and proposals are stored in the external project context.

## 5. Human Decisions

List proposals:

```bash
python3 -B scripts/evolution.py list \
  --project-id <project-id> \
  --context-root ~/.codex/project-context
```

Accept a proposal direction:

```bash
python3 -B scripts/evolution.py decide \
  --project-id <project-id> \
  --context-root ~/.codex/project-context \
  --proposal-id <proposal-id> \
  --decision accept \
  --actor "<human-decision-maker>" \
  --rationale "The evidence matches the problem; create a separate implementation task and run complete regression."
```

`ACCEPTED` means the direction received human approval. It does not authorize implementation. Real modification still requires:

```text
New Task ID
  + current Git baseline
  + explicit modification scope
  + independent Approval
  + Execution Guard
  + regression validation
  + Finalization readback
```

## 6. Rollback

All new V5.1 runtime state is under:

```text
~/.codex/project-context/<project-id>/evolution/
```

Keep this directory as historical audit evidence when rolling back program versions; older releases do not read it automatically.

Do not alter history by deleting `proposals.jsonl` or `decisions.jsonl` manually. Restore damaged data from backup; hash-chain failure fails closed.

## 7. Custom Policy

Default policy:

```text
config/evolution-policy.json
```

Use a custom policy:

```bash
python3 -B scripts/evolution.py run \
  --project-id <project-id> \
  --context-root ~/.codex/project-context \
  --policy /absolute/path/to/evolution-policy.json \
  --dry-run
```

Unknown fields, invalid thresholds, or out-of-range values cause rejection rather than silent ignore.

## 8. Migration Boundary

V5.1 does not copy an external TypeScript implementation. It reimplements the governance concepts using this package's Python runtime, external project context, Evidence, and Approval contracts.

Priorities:

1. One authoritative implementation.
2. Deterministic analysis.
3. Traceable evidence.
4. Proposals cannot execute automatically.
5. Append-only state and hash chains.
6. Sensitive-field redaction.
7. No conclusion from insufficient data.
8. Every real modification continues through the established execution and approval path.
