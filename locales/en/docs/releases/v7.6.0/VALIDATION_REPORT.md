# V7.6.0 Validation

The current implementation candidate passed canonical Linux package validation: 284 package tests and 144 runtime tests, with unchanged source and snapshot hashes during execution. See the generated [package report](PACKAGE_VALIDATION.json). Only this report was organized afterward. Final Windows/Ubuntu package checks, reproducible bilingual builds and the eleven-version host matrix are established by the [exact tag workflow](https://github.com/JimmyVGDY/codex-long-term-assistant-skills/actions/workflows/release.yml) and [public release assets](https://github.com/JimmyVGDY/codex-long-term-assistant-skills/releases/tag/v7.6.0).

The first PR CI passed both Linux targets and the host matrix. Windows runtime tests completed with short-path identity errors and noncanonical expected-path assertions, rather than timing out. The repair normalizes budget roots through existing safe_path checks, preserves cross-repository rejection and all read/time limits, and passed local targeted checks for every failing path plus a real Windows 8.3 alias regression. Two earlier complete Windows runs on the local account timed out; those separate historical failures are not rewritten as full passes. Platform-specific skips do not establish platform coverage.

The initial functional candidate passed business and protected-input checks in 11 of 11 natural samples; workflow outcomes were 10 PASS and one OUTSIDE_SCOPE block. A separate stale-index replay passed without replacing that blocked sample. Two fresh installed-candidate tasks verified initial scan, follow-up reuse, stable capability IDs and stale-receipt invalidation. These bounded examples do not establish universal reuse reliability or hot reload of an already-open Desktop session; versioned installation and fresh-process loading are checked separately.

An isolated offline source trial reused existing frontend, backend and provider interfaces and passed type, build, rendering and backend checks. An oversized lockfile retained CONTEXT_UNCONFIRMED; real business source was not sent to a model for that trial. An earlier synthetic probe unexpectedly reached the model service; its exact payload remains UNKNOWN and the earlier zero-model-call claim was withdrawn.

Findings from the initial implementation's logical-read-only independent review were repaired. The release-stage short-path repair and subsequent evidence reconciliation were checked by the primary coordinator and are not another independent review. No net token saving, P95 improvement or break-even point is established. Tag, public Release, Pages deployment, account version and actual loading require separate readback; package tests do not replace that evidence.
