# V7.16.0 release notes

This release aligns actual Codex Desktop gates with the current policy: valid absolute paths were rejected, index and review gaps halted work, late receipts retained holds, and continuation/message identities were incompatible.

- Native writes retain specific causes and executable preparation arguments while checking identity, targets, prestate, and receipts.
- Installer registrations enter the entrypoint inventory. Execution and review scripts default to nine GPT-6 profiles, with Sol/medium for unknown work.
- Missing optional index or phase material permits scoped continuation with separate verification. Unrelated child-ledger failures do not deny parent reads.
- Long records, partial lines, and late receipts reconcile the original handle. Continuations reserve a new attempt in the original root, preserving historical planning units.
- Authorized LIGHT, STANDARD, and STRICT roots share admission checks. Agent IDs resolve through native identities in the same root.

Codex Desktop is the sole product target. Planning units are not fees; logical-readonly is not system isolation. V3/V4/V5 replay stays compatible. See [Desktop gates and recovery](../../DESKTOP_GATE_RECOVERY.md) and the [validation report](VALIDATION_REPORT.md).

Public tags, final assets, installation, and native readback use separate GitHub Release evidence. Version numbers do not prove runtime effect.
