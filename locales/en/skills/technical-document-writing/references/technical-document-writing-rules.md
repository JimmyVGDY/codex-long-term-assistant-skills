# Technical Documentation and Formal Report Rules

> V5.0 retains the on-demand references introduced in V4.1. Read this index first and load only the sections needed for the current task; never load every file merely for formality.

## Loading Index

| Reference | Content | Load When |
|---|---|---|
| `document-scope-evidence.md` | Document objectives, prerequisite discovery, and evidence management | Starting a formal document or identifying audience, purpose, and factual sources |
| `document-structure-language.md` | Structure, language, tables, code, and diagrams | Organizing sections, prose, tables, code, and Mermaid |
| `document-types-comparison.md` | Document-type playbooks and multi-option comparison | Technical solutions, architecture, APIs, databases, incidents, management reports, and technology selection |
| `document-maintenance-quality.md` | Existing-document changes, memory isolation, quality review, and delivery | Updating existing documents, performing quality checks, and delivering the final result |

## Loading Principles

- Identify the primary problem domain for the current phase, then load the minimum necessary references.
- Cross-domain work may combine references, but each reference must have one explicit responsibility.
- After the phase ends, unrelated references are no longer active context.
- Concrete code, configuration, logs, and runtime evidence always take precedence over general reference guidance.
