# 门禁恢复与结果表达

English: [Gate recovery and result reporting](gate-recovery-policy.en.md)

门禁判断“当前具体动作是否可执行”，证据判断“已确认发生了什么”。缺少可选资料或审计回调，不能自动变成全任务停工、重复授权或重启要求。继续执行不代表把 UNKNOWN 改为 PASS。

## 统一处理

| 情况 | 处理 |
|---|---|
| 非关键材料、历史样本、质量卡或可选检查缺失 | 使用既有默认或降级路径，记录缺口 |
| 锁竞争、暂时读取失败、上下文暂未落盘 | 在原调用上做有界恢复；不重复启动收费调用 |
| 文件写入后审计回调缺失 | 读回原 Operation 与目标文件；不能为补回执盲目重放写入 |
| 有原生结束记录但业务结论 UNKNOWN | 显示运行已结算；业务或复审结论另读对应证据 |
| 基线变化或许可过期 | 为受影响动作重新准备；原失败与花费保留 |
| 已确认越权、身份冲突、哈希损坏或真实超额 | 限制对应动作，继续不受影响的已授权工作 |
| 已有明确且仍适用的用户授权 | 复用授权；脚本准备或证据缺口本身不要求用户再确认 |
| 宿主权限拒绝 | 保留宿主限制；插件范围登记不能授予宿主权限 |

## 本轮实际入口审计

本轮以 v7.16.2 为基线，覆盖安装器生成的三个受管 Hook、十二项策略门禁及执行、安装、观察控制器。冻结的旧 V3/V4/V5 账本继续原语义回放，不替换历史解释器。

| 入口 | 审计结果与修正 |
|---|---|
| cp_gate.py / Operation prepare | 仓库写入与仓库外任务产物分流；保留项目身份和真实写入许可 |
| 路径与索引 | 普通长文件名不再触发正文熵规则；敏感路径、明确凭据特征、链接和越界仍校验；缺索引可降级 |
| PostTool / Operation finish | 审计缺口返回读回下一步，不笼统阻断或声称没生成文件；重复的相同完成回调保持幂等 |
| cp_context.py | 新任务范围进入原根路由；回调失败只记上下文审计缺口，不指令整个任务“未完成” |
| cp_hook.py / 预算初始化 | 多任务范围隔离；预算路由异常不阻断无关主任务读写 |
| 派发许可、并发、未来预留、重试 | 复用原子预占与已授权模板；真实超额仍不能被任务改名、续跑或切换冲销 |
| 模型选择、上下文就绪 | 缺可选材料使用默认或受限上下文；不恢复统计资格墙或自动升档 |
| 前审、后审、修复复审 | 缺证明不伪造通过；集中裁决确认的缺陷只限制相应高风险动作 |
| 工作流阶段、验证、最终声明 | 未验证阶段允许可逆工作；实际提交、推送、发布、安装与生效分别读回 |
| 安装兼容和事务 | 缺运行读回保持待验证；包哈希、安装目标、事务一致性与必需宿主协议继续核验 |
| 同聊天交接、任务完成 | 旧字节和未结调用保留；晚到事件归原任务；新读取器匹配后才发布新路由格式 |
| 观察 health | 坏数据限制对应分析，不把观察故障变成业务执行门禁 |

“合并后例行检查仍运行”与“合并前必需检查通过”并不矛盾；继续收集后续结果。未重启不等于未生效：先核对当前组件和实际链路，只有新配置确实要求重新加载时才讨论重启。宿主结果分类 UNKNOWN 不是自动重启依据。

复审范围支持原有字符串列表和有界结构化对象。新增说明字段保留为元数据；只有明确的顶层 packet_sha256、context_sha256 等证据字段参与绑定，嵌套说明不能冒充证明。对象受字段数、深度、节点数与字符串长度限制，错误摘要仍被拒绝。原报告不重写；已绑定且通过的相同材料不因范围外未验证项或新增说明字段而重复派发。

追加批准以原账本为准。allowance-recover 和 allowance-status 会移除已处理申请的陈旧“待批准”视图，返回继续原调用或使用现有额度的下一步。原问题、批准、撤销和消耗仍保留；状态刷新不产生新授权。

Windows 普通路径与命名空间路径只有在文件系统确认指向同一实体，且规范路径、文件身份和头部摘要一致时才视为同一原生来源。保留历史路径拼写、任务引用和批准记录；路径别名不触发重新授权，真实文件替换仍拒绝。来源诊断只返回有界契约码或异常类型。

## 原生结束回调缺失

子任务已经结束而 SubagentStop 丢失时，可在原控制器执行 `review_controller.py reconcile --review-dir <原目录>`。派发前也会做有限读回。恢复只读取该根已登记子任务的宿主转录，核验身份、项目、头部摘要、创建回执、预占时间和唯一回合；只有明确的原生结束事件才能结算，单独出现最终回答不够。

读回结算保留原费用、尝试和任务归属，业务结果仍可为 UNKNOWN；取消记录保持 CANCELLED。证明来源标为原生转录读回，不伪称收到 SubagentStop。重复对账及迟到回调不重写既有终态。身份不匹配、多回合歧义、缺失记录或有界读取不足时保留在途状态并继续其他可行工作；不手工释放额度或补造回调。

创建回执也缺失时，协调者可在原控制器的 reconcile 命令中通过 `--child-transcript <实际原生子任务文件>` 提供最多两个候选来源。路径只定位记录，不能证明创建；仍须核对原生父会话、任务名、角色、项目、原预占以及头部时间。恢复不补造 SubagentStart、上下文交付或业务 PASS。

复审回执先冻结最小元数据，再写入终态；只有真实账本终态与冻结证明完全一致，才发布有效回执。暂存仅含报告摘要和来源引用，不保存回答正文。结算后回执发布失败可由同一对账入口补发，不重新计费，也不读取后来追加的回答替换原报告。证明冲突仍拒绝对应回执。

## 写入回执的边界

写前拒绝表示这次工具尚未执行；写后审计失败不证明文件未改变。主协调者必须先读回文件、原调用和后续验证，分别描述文件结果与审计完整性。真实身份或命令冲突仍限制该结果确认。不能手工补造原生回调、放宽文件系统沙箱或把已有许可用于不同补丁。

Operation 的时限继续用于区分当前许可与过期证据；过期不等于撤销已经完成的文件修改。缺失回执保留 UNKNOWN，后续安全工作不因此永久冻结。历史回执缺口不会被新版本追溯改为 PASS。
