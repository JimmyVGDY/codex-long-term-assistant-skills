# V5.0 升级说明与迁移指南

## 1. 升级目标

V5.0 从 V4.2 升级时不替换原有 9 个 Skill、7 个 Reviewer、模型分级、Review Packet、Review Controller 和 Checkpoint 工具。新增的是一个仓库外的轻量治理运行时，用于解决跨项目工作中四类常见错误：项目串线、授权复用、旧证据误用、最终状态误报。

## 2. 兼容性

| 项目 | V4.2 → V5.0 |
|---|---|
| Skill 名称 | 不变 |
| Reviewer TOML | 不变 |
| `LIGHT/STANDARD/STRICT` | 不变 |
| `economy/balanced/deep` | 不变 |
| Luna/Terra 四级路由 | 不变 |
| `review_packet.py` / `review_controller.py` | 保持兼容 |
| `checkpoint.py` | 保持兼容 |
| `execution_guard.py` | 原命令兼容，状态自动迁移到 schema 3 |
| 现有 `config.toml` | 安装器仍不自动修改 |
| 项目仓库 | 默认不写入治理状态 |

## 3. 新增安装内容

```text
${CODEX_HOME}/
├── runtime/cp_runtime/       # V5.0 共享合同与运行时
├── tools/cp-runtime.py       # 命令入口
├── project-context/          # 首次 Onboarding 后按项目创建
├── skills/                   # 原有 9 个 Skill
├── agents/                   # 原有 Reviewer
└── AGENTS.md                 # 合并受管规则
```

卸载 V5.0 时不会自动删除 `project-context/`，避免误删既有项目记忆与证据。需要删除时必须单独确认。

## 4. 推荐升级步骤

### 4.1 校验安装包

```bash
python3 scripts/validate-package.py
```

### 4.2 Dry Run

```bash
./scripts/install-user.sh all --dry-run
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\install-user.ps1" -DryRun
```

### 4.3 安装与验证

```bash
./scripts/install-user.sh all
./scripts/verify-user-install.sh
./scripts/doctor.sh
```

### 4.4 继续合并 Codex 配置

安装器不会直接改 `config.toml`。继续按 `docs/CODEX_CONFIG_GUIDE.md` 合并 `[agents]` 配置，避免覆盖既有设置。

## 5. 首次项目接管

对正在维护的项目执行一次有界只读 Onboarding：

```bash
python3 "$CODEX_HOME/tools/cp-runtime.py" project-onboard \
  --repo-path /path/to/repo \
  --project-id project-a
```

工具只读取 Git 和仓库根目录附近的构建标记：

- 不访问网络；
- 不访问生产；
- 不运行构建和测试；
- 不扫描凭据；
- 不把推断入口标记为已确认事实。

生成后先检查：

- `project-profile.json` 中的 `unknowns`；
- 构建、测试、启动入口是否准确；
- 环境、数据敏感等级和数据所有权；
- 禁止扫描和禁止修改目录。

## 6. V4.2 任务状态迁移

旧 `execution-state.json` 第一次由 V5.0 `execution_guard.py` 读取时，会补充：

- `baseline_fingerprint`；
- `current_fingerprint`；
- `project`；
- `routing`；
- `authorized_actions`；
- `actions`。

旧任务默认标记为 `UNBOUND`，不会自动猜测 Project Profile。需要继续执行受保护动作时，应新建或重新初始化绑定项目的任务信封。

## 7. Approval 迁移原则

V4.2 的 `authorization.create_commit=true` 等布尔值继续作为请求方意图记录，但不能单独证明授权仍然适用于当前项目、任务、环境和代码基线。

V5.0 对受保护动作采用：

```text
明确明确授权
  → approval-issue
  → authorize-action（动作前校验并消费）
  → 外部执行动作
  → record-action（动作后读回）
  → finalize
```

`approval-issue` 不能自行推断明确同意。只有上层会话已经获得明确授权时才可调用。

## 8. 记忆迁移原则

旧 `CURRENT_TASK.md`、`PROGRESS.md` 和 Checkpoint 继续有效，但它们只是任务恢复事实源，不会自动进入 `project-memory.md`。

晋升流程：

```text
Checkpoint / Handoff
  → memory-project
  → 人工或受控规则审核
  → memory-promote
  → project-memory.md
  → knowledge-candidate
  → 后续跨项目审核
```

## 9. 回滚

恢复最近一次安装前状态：

```bash
./scripts/restore-latest-backup.sh
```

恢复器会校验：

- 备份目录必须位于受管 backup 根目录；
- Backup Manifest 完整性；
- 目标必须属于 V5.0 受管白名单；
- 备份内容哈希；
- 备份文件不能通过路径穿越写入其他目录。

## 10. 升级完成标准

- [ ] `verify-user-install` 通过；
- [ ] `doctor` 显示 9/9 Skill、Runtime 和 Tool 均存在；
- [ ] 至少一个项目完成 Onboarding 并人工校对 Profile；
- [ ] 新任务能绑定 Project Profile；
- [ ] 代码变化后旧 Evidence 会标记 stale；
- [ ] Finalization 对无证据的部署或生效声明返回 BLOCKED；
- [ ] Restore 在隔离环境中通过。
