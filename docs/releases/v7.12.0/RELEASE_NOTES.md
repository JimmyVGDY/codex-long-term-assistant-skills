# V7.12.0 发行说明

V7.12.0 是可靠性、验证证据和日常诊断优化候选版本，继续以 Codex CLI `0.155.1` 为兼容锚点并保留 11 个稳定版窗口。本记录描述本地集成候选及本地安装读回；提交、CI、制品、公开发行和已打开会话生效仍是独立门禁。

## 候选变更与已执行证据

- F01 增加阶段感知的 SessionEnd 权限兜底。50 项定向回归和 16 次并发压力重复通过；根角色重叠拒绝、恢复回执认证、字段篡改拒绝和无密钥诊断隔离均在该范围内验证。
- F02 已完成三场景评估。候选快捷路径暂不交付并恢复原 LIGHT 规则；simple 工具调用中位数从 6 降至 5（-16.7%，未达到 20% 建议目标），时长未改善，resume 的基线为 5/5 通过而候选 4/5。该结果不将质量下降或失败归因于规则本身，也不宣称稳定降本、通用效率收益或因果关系。
- F03 保留每次追加的全历史验证，只复用同一次运行中的身份读取。100、1,000、10,000 三种规模各 20 个样本已执行；该验证不宣称渐进复杂度得到改良。
- F04 提供显式 `status --quick`，默认 `status` 仍执行完整检查。50 项定向测试通过；当前安装环境同账户、并行原生采样的 20 对样本中，完整检查中位数为 2924.6905 ms（p95 3521.541 ms），快速检查为 110.248 ms（p95 115.587 ms），局部下降 96.23%。`--quick` 不提供完整验证或授权，不能外推到其他账户、宿主或公开版本。
- F05 增加受控演进治理的正反例与阶段路由回归，52 个用例已通过。16 个原生宿主用例实际为 8 通过、8 失败：其中 7 个因外部 `powershell-safe-invocation` 混入插件集合，另有中文阶段标识未匹配 implement/review；宿主验收未通过，已确认报告集合范围与阶段 ID 的 runner 契约缺口，修正协议后的全新固定验收正在进行。
- F06 将完整验证器的能力结论绑定到实际发现和执行的 unittest 标识与结果；缺失、全跳过、失败、错误、subTest 失败、意外成功、超时或报告损坏均不会投影为 `PASS`。完整执行后，19 组能力重投影通过，另有 9 项定向证据测试通过。
