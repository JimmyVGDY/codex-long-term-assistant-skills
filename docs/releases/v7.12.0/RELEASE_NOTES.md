# V7.12.0 发行说明

V7.12.0 是可靠性、验证证据和日常诊断优化候选版本，继续以 Codex CLI `0.155.1` 为兼容锚点并保留 11 个稳定版窗口。本记录描述本地集成候选及本地安装读回；提交、CI、制品、公开发行和已打开会话生效仍是独立门禁。

## 候选变更与已执行证据

- F01 增加阶段感知的 SessionEnd 权限兜底。50 项定向回归和 16 次并发压力重复通过；根角色重叠拒绝、恢复回执认证、字段篡改拒绝和无密钥诊断隔离均在该范围内验证。
- F02 已完成三场景评估。候选快捷路径暂不交付并恢复原 LIGHT 规则；simple 工具调用中位数从 6 降至 5（-16.7%，未达到 20% 建议目标），时长未改善，resume 的基线为 5/5 通过而候选 4/5。该结果不将质量下降或失败归因于规则本身，也不宣称稳定降本、通用效率收益或因果关系。
- F03 保留每次追加的全历史验证，只复用同一次运行中的身份读取。100、1,000、10,000 三种规模各 20 个样本已执行；该验证不宣称渐进复杂度得到改良。
- F04 提供显式 `status --quick`，默认 `status` 仍执行完整检查。50 项定向测试通过；20 对同账户并行原生采样（旧 payload `948c`）中，完整检查中位数为 2924.6905 ms（p95 3521.541 ms），快速检查为 110.248 ms（p95 115.587 ms），局部下降 96.23%。该指标尚未在当前最终 payload 上重新测量；`--quick` 不提供完整验证或授权，不能外推到其他账户、宿主或公开版本。
- F05 增加受控演进治理的正反例与阶段路由回归，52 个用例已通过。原 16 个独立宿主任务为 13 通过、3 失败，失败记录保留。固定验收 profile 保持不变，13 个原始证据字节与 3 个定向补充任务组合后形成 16 个实际独立任务的 `HOST_FINAL_REPORT`：16 个观察、16 个通过、无缺失。它不声称单一 cohort 的通过率，也不是独立 router trace；结论只覆盖该 profile。
- Windows 原生 Hook 启动方式已修复：Codex 的 `environment.shell=WindowsPowerShell` 会将旧的双引号路径命令解析为 `UnexpectedToken`；静态 Hook 改为固定 `cmd.exe /D /V:OFF /S /C` 包装器，PreToolUse 使用显式 argv，危险 shell 字符失败关闭，POSIX 启动方式未改。受管账户安装已以 exit 0 完成；真实原生 Hook 生命周期仍待单独验收。
- 安装器仅更新 `hooks.json`，不会覆盖 `hooks.state` 的既有可信摘要；新 Windows 包装器会让当前 10 条受管 Hook 显示为 modified。升级后请在 Codex 正常 `/hooks` 界面审查并信任这 10 条 Hook，不使用 bypass。正式 full status 通过不等于该信任步骤或真实 Hook 生命周期已经完成。
- F06 将完整验证器的能力结论绑定到实际发现和执行的 unittest 标识与结果；缺失、全跳过、失败、错误、subTest 失败、意外成功、超时或报告损坏均不会投影为 `PASS`。完整执行后，19 组能力重投影通过，另有 9 项定向证据测试通过。
