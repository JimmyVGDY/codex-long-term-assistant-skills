# v3.1 设计说明：日志与可观测性分析 Skill

## 一、设计目标

v3.1 把日志分析从多个技术 Skill 中分散的附属检查项，抽象为独立、可自动匹配的横向工作流，同时保持领域职责和权限边界清晰。

核心定位：

> 跨环境、跨技术栈的日志与可观测性分析编排 Skill；技术领域 Skill 提供具体机制解释，质量交付 Skill 只在进入修改和交付阶段时加载。

## 二、为什么独立成 Skill

日志输入可能来自本地文件、上传压缩包、开发测试环境、远程服务、生产容器、Kubernetes、Java/Python 应用、数据库和中间件。它们共享一套分析方法：

```text
确认范围与时区
    ↓
日志清单与完整性
    ↓
异常聚类
    ↓
跨来源时间线
    ↓
证据分级与候选根因
    ↓
低风险验证步骤
```

如果只放在生产操作或某个技术 Skill 中，会导致范围过窄或职责重复。

## 三、职责边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| `log-observability-analysis` | 日志输入、范围、时间线、聚类、证据、验证和只读模式 | Java/Python/数据库全部底层规则、代码修改和部署 |
| Java/Python/数据技能 | 解释具体堆栈、线程、事务、Worker、中间件和基础设施机制 | 通用日志编排 |
| `engineering-quality-delivery` | 从分析进入修改、测试、Git 和环境操作后的门禁 | 普通只读日志分析 |
| `long-running-task-memory` | 多轮、跨会话日志排障的检查点 | 一次性单文件分析 |
| `technical-document-writing` | 正式故障报告和复盘文档 | 原始日志分析本身 |

## 四、四种执行模式

1. **静态文件分析**：可受控解压、分块读取和临时解析，不覆盖原文件；
2. **本地运行环境**：查看本地进程、容器和日志，写操作单独授权；
3. **远程非生产只读**：限制扫描和查询成本，不因非生产自动获得写权限；
4. **生产只读**：严格限制时间窗、行数、文件范围和查询成本，禁止修改、清理、重启、部署、切流和数据写入。

## 五、多 Agent 边界

日志 Skill 支持但不默认多开 Agent：

- 普通单文件、单服务任务由主 Agent 完成；
- 跨多个服务、组件或长时间线时，可按应用、数据库、中间件、基础设施、安全或时间线维度并行；
- 子 Agent 只读并返回结构化结果；
- 主 Agent 统一时区、去重、处理冲突并归并证据；
- 日志分析子 Agent 不等于代码 Reviewer，不自动触发代码复审 Skill。

## 六、安全与资源

- 日志可能包含隐私、密钥、日志注入和外部输入；
- 大文件优先流式处理，压缩包限制文件数、大小和膨胀率；
- 生产只读命令也可能产生 CPU、磁盘、网络和数据库负载；
- 日志缺失、采样、乱序和时钟漂移必须进入结论限制；
- 时间相关性不能代替因果证明。

## 七、渐进加载

`SKILL.md` 保留触发条件、强制步骤、四种模式和组合边界；完整流程放入 `references/`，报告模板放入 `assets/`。这符合 Codex Skills 的渐进加载方式，并避免常驻提示词膨胀。
