# 桌面端模型选择、思考收益与预算审批

## 范围与启用边界

产品仅支持 Codex Desktop。内部管理、构建和安装脚本不构成独立 CLI 产品支持。
主 Agent 保持当前选择。登记 Reviewer 的 V4 目录包含六个型号的 Low、Medium、High，
共 18 个评测组合；新生产候选池为 GPT-6 的九个组合，并按场景逐项取得资格。
目录登记、模型可选、预算可负担都不直接证明审查质量。

V4 是显式启用的 `reviewer-matrix-v4 / quality-gain-routing-v1`。
没有已批准的场景资格时返回 `CALIBRATION_REQUIRED`；不把测试夹具晋升为资格，
也不在账本中途切回 V3。已有策略和初始化前明确选择的兼容路径使用
[冻结 V3 规则](https://github.com/JimmyVGDY/codex-long-term-assistant-skills/blob/master/skills/multi-agent-independent-review/references/reviewer-model-routing-v3.md)。
V1/V2/V3 的策略文件、费用语义、旧账本和结果解释器继续保留。

## 型号定位与评测假设

官方定位用于安排比较案例；具体审查资格由本项目同场景结果决定。

| 型号 | 定位与优先评测范围 | 兼容决定 |
|---|---|---|
| GPT-6 Luna | 聚焦、高频、成本敏感的任务；机械核对与边界清楚的逻辑审查 | 新候选，Low/Medium/High 分开验收 |
| GPT-6 Sol | 复杂编码与 Agent 工作流；业务逻辑、状态流转、跨接口审查 | 新候选，不能按旧 Sol 权重直接换名 |
| GPT-6 Astra | 困难的端到端推理；跨领域约束与有证据的冲突裁决 | 新候选；高风险不自动选 Astra/High |
| GPT-5.6 Luna | 原有成本敏感任务的历史基线 | 保留既有 Low/Medium；High 仅进入新评测目录 |
| GPT-5.6 Terra | 原有能力与成本折中的历史基线 | 保留既有 Medium/High；Low 仅进入新评测目录 |
| GPT-5.6 Sol | 原有复杂专业任务的历史基线 | 保留 Low/Medium/High 兼容路径 |

依据：[官方模型目录](https://developers.openai.com/api/docs/models/all)、
[模型选择指南](https://developers.openai.com/api/docs/guides/model-selection)。
这里没有宣称任何两个型号在本项目上的实测胜负。
Worker、Explorer 暂时仍为原四档，上限 `gpt-5.6-terra + high`。
所有自动派发禁止 xhigh、max、ultra。

## 思考强度的边际收益

Low 优先评估证据充分、路径短、判断边界清楚的工作；Medium 评估多步推演；
High 评估需要检查竞争假设、复杂状态或跨约束冲突的工作。
这些是实验假设，不能把强度名称换算成固定质量加分。

同一型号的 Low→Medium、Medium→High，以及跨型号的 Luna High→Sol Low、
Sol High→Astra Low，分别使用预登记的配对比较。相同材料、工具权限、判定标准、
案例与重复次数保持固定。提高强度与换型号都可能没有收益，或带来更多误报。
请求组合只表示发起的 model/effort，不读取或推断后台实际运行型号。

## 三层判断

1. **资格**：先匹配角色、阶段、语义/推理/风险范围、标签、上下文档、工具、速度模式
   和提示契约，再核验资格卡。严重遗漏、权限越界不能由更多普通命中抵消。
2. **收益**：在合格且资源可行的组合中，以计划成本最低者为经济锚点；同成本比较耗时，
   再按 profile ID 确定性裁决。升档或换型号必须有同场景配对收益依据。
3. **预算审批**：选择结果尚未授权。Hook 重新核对绑定、版本、基线和证据后，
   在同一个根账本锁内消费单次许可并预占资源，同时保留后续预审、复审和返修额度。

| 模式 | 选择规则 |
|---|---|
| economy | 选择经济锚点 |
| balanced | 质量收益下界至少 3 个百分点，成本不超过锚点 2 倍，耗时不超过 1.20 倍 |
| deep | 在真实资源约束内选择有证据的质量收益；近似最优差不超过 1 个百分点时优先较低成本 |

风险等级 3 使用 deep 判断，但不增加预算，也不强制选择最贵组合。
预算、次数、Astra 次数、Astra High 次数、并发、深度以及角色/阶段额度分别核验。
后续保留量来自一套完整可行分配，不能把各模型不同资源的最小值拼在一起。

## 评测与成本证据

至少 30 个独立案例只是样本数量下限。绝对通过率底线为 90%，配对非劣界为
5 个百分点，误阻断差异界为 2 个百分点，统计区间按预登记比较族分配显著性预算。
区间未达到条件时仍不合格；更多比较通常需要更多案例。
不能复用同一回执充当多次调用，也不能把同一个任务拆成多个独立案例。

成本卡分开保存计划成本、预占单位和耗时。当前桌面适配器没有可归属到单次调用的
真实计费回执，因此可使用明确标记的 `declared_proxy`，不能将 API 单价或账户总体用量
冒充单次桌面成本；生产加载拒绝缺少真实来源的 `measured_codex_credits`。
原生试验耗时是预占至停止回调的观察时长，不是纯模型推理时间。

评测完整性、资格计算、卡片发布是三个独立步骤。只有完整真实桌面调用来源、主协调者
判定和绑定到精确卡片/消费范围的发布批准，才能供生产根任务使用。
发布后的过期、撤销或修订变化会阻止后续派发。

## 桌面绑定与恢复

`scripts/routing-v4.py` 是桌面插件的内部管理入口。
`bind-desktop` 按根会话和仓库指纹登记账本，不依赖子进程修改桌面父进程的环境。
环境显式绑定与登记路径冲突时拒绝。关闭后的登记保留墓碑，避免预算重置或静默降级。

派发使用精确命名 key，或独占的 `CP_REVIEW_DISPATCH/2` 一次引用；两种形式不能混用。
正文摘要、独立上下文、角色、组合、基线和阶段都与许可绑定。
未知回执保持未关联，通用 status、超时或取消请求均不构成退款依据。
只有可信未启动证明可退单位，尝试次数不退。重复调用和乱序回调按根账本恢复。

| 当前 V4 对象 | 版本 |
|---|---|
| 根预算 / 审查状态 / 审查结果 / 观察样本 | 4.0 / 9 / 6 / 4.0 |
| 阶段计划 / 桌面能力 / 评测清单 | phase-plan/1 / desktop-capability/1 / routing-evaluation/1 |

V9 在不可变结果和根账本之间恢复投影，保存明确结论；有待派发许可、在途调用、
缺失结果或未解决阻塞时不能关闭为 PASS。
观察报告重新读取账本、结果和最终化证据，按项目、策略、场景、成本口径分组。
历史观察不证明当前代码通过，也不会自动修改模型、预算或配置。

完整字段、事务及失败恢复见[数据契约](MODEL_ROUTING_V4_CONTRACTS.md)。
