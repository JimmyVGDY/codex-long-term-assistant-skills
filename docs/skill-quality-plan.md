## 1. 目标、范围与授权

目标是把现有 Skill 的操作流程写得更具体，让实际产物可以核验，并通过可复用的对照实验判断优化是否有效。继续复用现有项目绑定、预算、复审、安装和交付机制。

| 编号 | 必须交付的优化 | 可验收结果 |
|---|---|---|
| W01 | Skill 产物对照评测入口 | 同任务旧版与候选版的产物、断言、成本指标和人工判断可对照、可追溯。 |
| W02 | 技术文档陌生读者测试 | 发现文档未表达的前置条件、作者上下文、歧义和不可执行步骤。 |
| W03 | 前端设计流程 | 设计依据真实内容、用户任务及现有设计系统，并经实际渲染复核。 |
| W04 | Skill 触发评测增强 | 覆盖口语、近邻负例、多意图和阶段变化，区分漏触发、误触发与过度加载。 |
| W05 | 浏览器验收流程 | 就绪检查、操作、断言、截图与日志、资源回收形成可执行流程。 |
| W06 | MCP 工具设计与验收 | 工具合同有具体范例，并通过多工具任务、分页及异常与权限案例验收。 |

立项后用户已明确要求按本计划执行至提交、推送和公开发布完成，并指定 7.16.2 为实施基线。上述直接指令是当前执行授权来源；计划文件和 Evidence 不另行授予权限。实验、安装、部署和重启按实际任务范围与既有门禁处理，不重复索取已经明确授予的权限。优化提案的 `execution_authorization=NONE` 不变。

这是人工指定的优化项目，不冒充由跨任务统计自动生成或已验证收益的 Evolution Proposal。当前没有运行统计演进分析、登记收益结论或修改路由策略。

### 1.1 范围约束

- 保持现有 10 个 Skill。新增内容优先进入对应 Reference、模板、样例和维护工具。
- 不替换治理运行时、预算账本、审批合同、独立复审控制器或安装事务。
- 不自动改 description，不自动接受实验结果，不从业务会话默认收集完整 Prompt、回答、代码、日志或凭据。
- 不引入上游专用 SDK 或模型命令行、新模型账号、常驻评测服务或新的前端构建链。
- 不恢复冻结的旧模型统计资格门禁；沿用当前脚本决策与共享预算。
- 不迁入受限许可的文档生成资产，不扩展 Word、PDF、PPT 或表格生成能力。
- 正式源码与双语产品文档按仓库规范交付；任务状态、原始实验产物与控制记录保留在仓库外。

### 1.2 用户追加的门禁改进

本任务同时修复仓库外任务产物被误判为 PATH_ESCAPE、预算按整条聊天绑定、写后回执缺口造成的笼统阻塞，以及 UNKNOWN 被误当作未运行或必须重启的问题。保留项目身份、文件权限、来源完整性和真实预算限制；按独立目标建立任务，原任务的修复、续跑、拆分及子 Agent 继续沿用原账本。复审与执行追加分开绑定角色，新增版本先确认已安装读取器匹配。详见[任务预算](operations/task-budget-scope.md)、[产物范围](operations/artifact-scope.md)和[门禁恢复](operations/gate-recovery-policy.md)。

一个总项目、六个工作包。每个工作包形成可单独审查、验证和回滚的边界；提交、推送和公开发布沿用本任务已明确授予的授权。

| 阶段 | 交付 | 依赖 | 放行证据 |
|---|---|---|---|
| S0 | 复核集成基线，冻结样例、指标、变更清单和实验预算 | 实施授权 | 身份与范围一致；冲突只限制相关动作。 |
| S1 | W01 最小评测入口与离线查看页 | S0 | 兼容、异常、路径及展示边界通过，结果可读回。 |
| S2 | W02 文档流程、W03 设计流程 | S1 基础证据格式 | 各有入口、正反例、小样本行为结果。 |
| S3 | W04 路由评测 | S1、W02/W03 候选入口稳定 | 新旧合同兼容、开发集与最终集隔离、观察来源真实。 |
| S4 | W05 浏览器流程、W06 MCP 专项 | S1；W03 提供页面样例 | 页面操作与回收、工具组合与权限案例通过。 |

## 4. 六个工作包

下文保留各工作包的设计与验收要求；实现文件以当前源码为准，优先扩展同职责资产，并保留需求与验收编号。

### W01：Skill 产物对照评测入口

**目标。** 可核验地判断候选是改善结果、产生回归，还是仅增加成本。先交付比较能力，不预设一定有收益。

**实现。** 拟新增 `scripts/skill-eval.py`、`tests/test_skill_eval.py`、`tests/fixtures/skill-eval/`、`docs/SKILL_ARTIFACT_EVAL.md`。必要时抽取旧脚本纯函数复用，保留旧命令及数据语义。使用本地静态 HTML 展示，不新增常驻服务或构建链。

**流程。** 显式选择任务与旧/新规则 → 准备独立目录 → Desktop 独立任务执行 → 导入证据 → 程序验证产物和不变量 → 展示比较 → 人工判定。脚本不默认调用模型或远程写入。

**记录合同。** 记录案例与输入摘要、源提交与规则摘要、请求型号/强度、工具权限、环境、样本 ID、产物相对路径及摘要、检查项结论与证据位置、耗时和有来源的计数。未知用量保持 UNKNOWN；请求型号不冒充后台实际型号证明。公开合成输入可以保存原文，业务原始会话不进入默认采集。

**隔离。** 产物和人工反馈在仓库外，独立评测清单引用旧 UX 结果；不扩展旧白名单容纳任意文本。旧/新版本保持相同权限、预算和强制安全边界，不关闭治理构造基线。答案和盲评版本映射仅向评估者提供；仅目录/指令隔离时称逻辑隔离。

**W01-A：工具验收。** 覆盖完整/缺失/损坏报告、不可比输入、重复样本、路径越界、链接/Reparse Point、保护文件改写、空产物及恶意 HTML。限制文件数量、单文件和总大小；展示时转义不可信文本，默认不执行产物代码、不加载远程资源。交互预览另经隔离确认。重算确定一致，失败证据不可被覆盖。

**W01-B：行为验收。** 选现有复用案例完成旧/新各一次端到端试跑，定位真实产物和独立断言。评价检查项本身是否能识别错误内容；文件存在不等于完成。可选盲评允许平局和证据不足。

**回滚。** 撤回本工作包入口/资产，旧复用与 UX 工具继续可用，实验与失败资料保留可读。

### W02：技术文档陌生读者测试

**目标。** 读者不依赖作者对话即可理解关键前提与步骤。

**实现。** 在 `skills/technical-document-writing/` 增加拟议 `references/reader-testing.md`、`assets/templates/reader-test.md` 和样例；入口及 `document-maintenance-quality.md` 按条件引用。

**触发。** 安装、部署、恢复手册，跨团队架构/决策文档或用户要求验证可执行性时采用。标点、局部术语、CHANGELOG、简单说明不自动启动独立读者。

**流程。** 冻结文档与目标读者 → 预先确定 5 个关键问题及标准 → 无作者上下文读者仅接收文档与问题 → 汇总答案、证据段落和缺口 → 集中修订 → 重验受影响问题。答案标准不交读者；事实仍另查源码或权威来源，理解测试不替代事实核验。

**W02-A。** 安装、失败恢复、架构决策三类合成文档，各有完整与故意缺失前提的版本。正确版本的关键问题均有文档依据；遗漏版本能定位关键缺口，不编造命令或权限条件补全答案。

**W02-B。** 每类做一组旧/新规则独立比较；关键恢复案例每个版本 3 次作一致性筛查。无独立读者能力时标记证据不足，不把作者自查当独立验证。

**回滚。** 仅撤回新增指针和资产，保留原质量维度与模板。

### W03：前端设计流程

**目标。** 设计选择服务于真实内容、受众和主要任务，并落实到渲染结果。

**实现。** 在 `skills/frontend-engineering/` 增加拟议 `references/design-workflow.md`、简短设计说明模板和样例，复用现有设计系统、质量与可访问性规则。

**流程。** 明确用户/页面任务/真实内容 → 查现有组件与设计系统 → 简短配色、字体、布局、交互及动效方案 → 对照需求修订 → 实现 → 目标尺寸截图自查 → 修复实际问题。已有产品继承现有规范；用户风格要求优先，不制定跨项目审美禁用清单。

**W03-A。** 新建公开页面、已有后台表单、设计系统局部扩展三类样例；各有桌面/移动尺寸渲染证据。按适用范围验证焦点、可读性、溢出、加载/空/错误状态及减少动效偏好。

**W03-B。** 按预登记的内容层级、任务完成、一致性与可读性评价，每类一组旧/新比较；局部扩展案例每个版本 3 次。检查是否无理由重做主题、换组件或升级依赖。截图存在、颜色数量或自称美观不算通过。

**回滚。** 撤回新增设计流程及指针，保持现有框架、安全和兼容规则。

### W04：Skill 触发评测增强

**目标。** 改善真实表述和相近任务的区分，同时控制不必要加载；效果通过观察确认。

**实现。** 扩展现有路由工具、用例、宿主验收说明及测试。保留旧 schema 和 required/optional/forbidden/max_active/phases 语义；不能兼容时显式版本化，不重解释历史结果。

**样本。** 首批新增 24 条人工合成候选：12 条应触发、12 条近邻负例，分技术文档、前端设计、浏览器验证、MCP 四组，每组 6 条。包含口语、多意图、阶段变化。按意图族分 16 条开发和 8 条最终验收，相关改写不跨集合；两集合均覆盖四组和正反例。最终集合不用于反复挑选描述。

**执行。** 固定请求型号/强度、安装版本、输入和权限，关键歧义案例独立重复 3 次。分别记录漏触发、禁止能力、超量与阶段错误。宿主最终自报保持 host_final_report 级别，只有实际可见的读取/调用证据才称执行轨迹；不能按期望补填。

**W04-A。** 原 52 条及宿主 profile 的结构/评分保持兼容；新例无 required/forbidden 冲突。安全与授权负例不得违规；其他失败如实计入，不通过放宽 optional 或标准消除失败。

**W04-B。** 描述变更只有在最终验收及质量底线满足时采用；无改善证据则保留评测能力、继续旧描述。最终集合泄露或参与调参后重建独立集合，旧结果与局限保留。

**回滚。** 恢复旧描述或用例，保留旧解析及结果；不自动改模型策略或历史账本。

### W05：浏览器验收流程

**目标。** 运行结论关联真实交互、正确环境和可恢复资源。

**实现。** 增加拟议 `skills/frontend-engineering/references/browser-validation.md`，扩展已有 `FRONTEND_VALIDATION_MATRIX.template.md`，提供少量合成场景。只在真实重复需求下增加小型辅助器，不默认安装浏览器或接管用户服务。

**流程。** 识别现有服务与测试入口 → 验证服务身份/页面就绪 → 从渲染 DOM 或截图定位 → 操作和断言 → 脱敏截图/相关错误取证 → 回收本次资源。构建、浏览器交互、后端真实集成分别报告。

**W05-A。** 覆盖静态页面、前后端分离、请求失败/空数据、重复操作/竞态四类，并包括用户已有服务。端口可连接不等于正确服务已就绪；不把网络空闲作为所有页面唯一条件，使用具体页面状态或元素断言。

**W05-B。** 采用项目已有测试及宿主支持的浏览器接口，遵守工具访问方式；辅助器使用参数数组、受控目录、有界超时。失败/取消只回收本次创建的浏览器、服务及子进程，保留用户服务。Windows 必验，其他平台分别记录状态。

**回滚。** 撤回流程或辅助器，恢复项目原验证入口，不全局按进程名或端口清理。

### W06：MCP 工具设计与验收

**目标。** Agent 能依据工具合同选择和组合能力，遇到错误或权限不足有可靠的下一步。

## 5. 统一验收与收益口径

### 5.1 三层判定

1. 实现验收：入口、格式、边界、兼容、异常和清理符合合同。
2. 行为验收：独立任务实际完成案例，有产物和独立核验；执行者自报不能单独判定完成。
3. 收益判定：可比条件下观察质量/成本差异。小样本只报告观察，不宣称普遍可靠或统计显著。

终态沿用 PASS/BLOCKED/FAILED/CANCELLED/PARTIAL/UNKNOWN。“已立项”“待实施”属于计划状态，不冒充运行结果。平局、证据不足、不适用不换算成成功。

### 5.2 基线、预算与实验

- S0 固定各案例输入、关键不变量、允许改动、评估者及可见资料；不可冻结的案例不计入可比结果。
- 旧/新采用独立任务与目录，保持请求型号/强度、工具权限、环境和初始文件一致；不推断后台型号。
- 以案例/独立任务计数，不用事件数或相关改写增加独立样本量。
- 规则或输入变化后相关验证/评审失效，保留旧结果并定向重验。
- 不预设 20%、30% 等改善数字。基线采集后预登记目标及允许退步边界，再冻结候选。
- 安全、权限、数据完整性和受保护输入必须全部通过；速度或主观评分不能抵消失败。
- S0 按案例数、版本数、重复次数及必要复审预留计算实际实验总量，由现有脚本和根账本控制；不足时分批执行，不能清零累计消耗或降低验收。
- 六项均进入结项矩阵。某项无收益时如实记录，保留有价值的评测能力，不以无依据的好评填满完成表。

### 5.3 定向与集成检查

工具行为变更后执行相关定向验证，重点包括 `test_reuse_eval.py`、`test_ux_benchmark.py`、路由阶段/宿主验收测试和新评测测试。具体命令从实际入口确认；拟议新文件不当成现成命令执行。

S5 按最终差异运行既有 `localization-audit.py --strict`、`check-links.py --strict`、`validate-package.py` 及受影响的文档/分发检查。新增源码、产品文档提供独立中英文版本及规范注释；同步受影响的清单、Payload 和本地化覆盖。版本矩阵按项目声明验证。

W01 的产物展示、路径和证据合同重点接受安全、数据及兼容审查；W04 重点检查路由兼容和证据；W05 重点检查取消、资源归属和权限。按实际风险复用现有独立复审机制，同轮收齐、归因后集中修复，不新建评审模型路由。

## 6. 风险、停止和恢复

| 风险 | 控制或停止条件 | 恢复 |
|---|---|---|
| 基线/其他 PR 变化 | 不混写 #24，每阶段核对 | 从确认后的当前状态继续，不覆盖他人改动。 |
| 流程负担增加 | 按条件加载，比较读取量/调用/确认次数 | 撤回无收益的强制步骤，保留可选维护能力。 |
| 评价泄露/过拟合 | 执行者不看 oracle/对方产物，最终集不调参 | 重建独立集合，保留旧实验局限。 |
| 产物注入/敏感数据 | 不可信展示、路径与大小限制、默认无远程资源 | 停止对应展示或导出，修复后用合成异常输入重验。 |
| 进程遗留/误清理 | 仅回收有归属证据的本次资源，覆盖取消路径 | 精确恢复，不按进程名全局杀进程。 |
| 轨迹或费用未知 | 保留 UNKNOWN 和证据级别 | 继续有来源的检查，补证据后再提高结论等级。 |
| 许可/宿主差异 | 固定上游，独立设计，具体目录核许可 | 不引入受限资产，按 Desktop 实际工具落地。 |
