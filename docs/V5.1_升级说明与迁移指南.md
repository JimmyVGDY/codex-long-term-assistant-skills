# Codex 跨项目长期技术助手 V5.1 升级说明与迁移指南

## 1. 版本定位

V5.1 在 V5.0“项目治理与证据闭环”的基础上，补齐以下受控自进化链路：

```text
执行反馈 / Review / Evidence / Checkpoint / Audit
                  ↓
            Self Observation
                  ↓
     Value & Complexity Analysis
                  ↓
        Optimization Proposal
                  ↓
        人工接受 / 拒绝 / 延期
                  ↓
       独立实施任务与显式 Approval
```

本版本的自进化严格限定为“观察、分析、提案和人工决策记录”。它不具备、也不模拟以下权限：

- 自动修改 Skill、Reviewer、模型分级或全局配置；
- 自动接受自己的提案；
- 自动创建 Commit、Push、部署、重启或生产写入；
- 自动把单项目经验提升为跨项目全局规则；
- 以 Evidence、Proposal 或 ACCEPTED 状态替代 Task Envelope 和 Approval。

所有优化提案的 `execution_authorization` 固定为 `NONE`。

## 2. 兼容性

V5.1 保留 V5.0 的 9 个 Skill、7 个 Reviewer、项目治理运行时、Task Envelope V2、Approval、Evidence、Checkpoint、Memory Projection 和 Finalization Integrity。

新增能力位于唯一权威目录：

```text
runtime/cp_runtime/evolution/
```

新增 CLI：

```text
安装包目录：scripts/evolution.py
安装后：${CODEX_HOME}/tools/evolution.py
```

V5.0 的项目上下文目录可直接复用：

```text
~/.codex/project-context/<project-id>/
```

V5.1 只会在该项目目录下新增：

```text
evolution/
├── snapshots/
├── assessments/
├── proposals.jsonl
└── decisions.jsonl
```

不会默认向业务仓库写入状态文件。

## 3. 升级步骤

1. 备份当前 `~/.codex` 配置和 V5.0 安装目录。
2. 使用安装包原有安装脚本安装 V5.1。
3. 执行原有 `verify` 和 `doctor`。
4. 执行 V5.1 专项校验：

```bash
python3 -B scripts/validate-v51-evolution.py
```

5. 对一个已完成 Project Onboarding 的项目执行只读观察：

```bash
python3 -B scripts/evolution.py observe \
  --project-id <project-id> \
  --context-root ~/.codex/project-context
```

6. 确认数据源和快照内容无误后，执行提案生成：

```bash
python3 -B scripts/evolution.py run \
  --project-id <project-id> \
  --context-root ~/.codex/project-context
```

## 4. 首次使用建议

首次运行建议使用显式数据源，避免项目历史目录中存在尚未纳入规范的 JSONL：

```bash
python3 -B scripts/evolution.py run \
  --project-id <project-id> \
  --context-root ~/.codex/project-context \
  --source feedback/execution-feedback.jsonl \
  --dry-run
```

`--dry-run` 只输出观察、评估和提案候选，不写入注册表。

确认后去掉 `--dry-run`，系统才会在仓库外项目上下文中保存快照和提案。

## 5. 人工决策

列出提案：

```bash
python3 -B scripts/evolution.py list \
  --project-id <project-id> \
  --context-root ~/.codex/project-context
```

接受提案方向：

```bash
python3 -B scripts/evolution.py decide \
  --project-id <project-id> \
  --context-root ~/.codex/project-context \
  --proposal-id <proposal-id> \
  --decision accept \
  --actor "<人工决策者>" \
  --rationale "证据与问题匹配，同意另行创建实施任务并执行完整回归。"
```

`ACCEPTED` 仅代表方向获得人工认可，不代表已经授权实施。真正修改仍需：

```text
新的 Task ID
  + 当前 Git 基线
  + 明确修改范围
  + 独立 Approval
  + Execution Guard
  + 回归验证
  + Finalization 读回
```

## 6. 回滚

V5.1 的新增运行状态都位于：

```text
~/.codex/project-context/<project-id>/evolution/
```

回滚程序版本时可以保留该目录作为历史审计记录。旧版本不会主动读取这些文件。

不得通过手工删除 `proposals.jsonl` 或 `decisions.jsonl` 修改历史。若数据损坏，应从备份恢复；哈希链校验失败时系统会失败关闭。

## 7. 自定义策略

默认策略位于：

```text
config/evolution-policy.json
```

使用自定义策略：

```bash
python3 -B scripts/evolution.py run \
  --project-id <project-id> \
  --context-root ~/.codex/project-context \
  --policy /absolute/path/to/evolution-policy.json \
  --dry-run
```

策略文件包含未知字段、非法阈值或越界值时会拒绝运行，不会静默忽略。

## 8. 迁移边界

V5.1 没有复制 AICTO 的 TypeScript 实现代码，而是基于本安装包现有 Python Runtime、仓库外项目上下文、Evidence 和 Approval 合同重新实现对应治理思想。

本版本优先保证：

1. 单一权威实现；
2. 确定性分析；
3. 证据可追溯；
4. 提案不可自动执行；
5. 状态追加写和哈希链；
6. 敏感字段脱敏；
7. 数据不足时不生成结论；
8. 所有真实修改继续走原有执行与审批链路。
