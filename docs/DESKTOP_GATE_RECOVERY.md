# 桌面门禁与恢复

本包仅支持 Codex Desktop。门禁区分“允许继续”和“已验证”：缺少索引、预审材料或统计样本时，返回默认或降级步骤；已确认的身份冲突、越界、账本损坏和额度不足只限制对应动作。内部管理脚本不构成独立 CLI 产品。

| 实际入口 | 职责 | 材料不足或暂时故障 |
|---|---|---|
| `cp_gate.py` | 原生文件工具的目标、前态、操作与回执 | 保留具体原因；提供带完整参数的准备动作。索引不可用时只停止消费索引，独立核验目标和前态 |
| `cp_context.py` | 已绑定子任务的上下文边界 | 主任务普通读取不查询子任务账本；旧受限子任务继续使用原边界 |
| `cp_hook.py` | 派发、续跑、回执与最小观察 | 原调用对账；保留费用状态和尝试，不以新派发替代未知调用 |
| `execution_guard.py` | 阶段和动作证据 | 缺可选材料可进入可逆实施或交付本地结果，不补造已完成门禁 |
| `review_packet.py` / `review_controller.py` | 审查材料与结果管理 | 新任务使用 G6；结果格式通过不等于原生复审或语义正确 |

安装器生成的全部受管注册必须能映射到入口清单。未知受管命令不能冒充第三方跳过检查。账户中真正的第三方 Hook 单独列为覆盖范围外。

## 客户端更新与项目选择

客户端内核变化与管理接口不兼容分别判断。管理命令和插件列表合同通过、但安装快照对应旧内核时，返回 `HOST_UPDATED_REVALIDATION_REQUIRED`：基础能力可继续使用，增强运行证据保持未验证。明确合同变化返回 `HOST_CONTRACT_INCOMPATIBLE`；超时等探测故障保持未知。只读诊断不刷新安装快照、不自动信任 Hook，也不证明预算或文件门禁已经生效。

聊天从临时目录首次选定项目时，来源 v2 使用精确匹配原生回合的 `turn_context.cwd`。会话头部继续表示初始目录；消息正文里的路径不能建立来源。新记录存放在会话下的独立工作目录分区，旧来源不被覆盖。来源登记不创建预算；已有根跨仓仍被拒绝。首次登记要求原目录没有 Git 仓库、当前会话没有既有预算归属，且已安装读取器与调用端一致。

来源 v2 对每条真实用户输入核验对应的原生回合目录证明，支持从同一宿主已定位文件中有界恢复历史目标；自动续跑、工具输出和缺少匹配证明的消息不作为授权来源。目录证明最多读取八个完整行窗口，每个窗口不超过 2,000,000 字节；历史来源每次最多额外定位四个回合，返回缺失计数，避免无限扫描。旧任务仍使用已冻结的来源引用。

新目录的额度游标使用独立 v2 格式，要求现有 TaskScope、预算根及原始用户来源引用完全一致。每条批准还须匹配该消息回合的项目目录；其他项目的回复不能扩额。缺少原生目录记录时保留游标，等待观察后恢复原请求，不要求重复回复。旧 v1 游标和预算流水语义保持原样；读取器不一致时不创建新格式授权。注册、写入和读取来源记录使用共同的有界锁，避免 Windows 读取句柄与原子替换竞争。

父会话来源、子任务身份与迟到回调共用账户根别名核验：根别名必须与已配置账户目录和原生会话文件分别为同一实体；会话目录内部链接、其他账户、相对的子任务路径和备用数据流仍被拒绝。

内部稳定组件窗口以 0.164.0 为本次候选基线，保留此前十个稳定发行版；版本窗口不是 Desktop 准入门槛。官方 npm 制品、标签提交与 Hook/结果源码摘要分别冻结，实际桌面 0.165.0-alpha.1.2 的观察单独记录。Windows 管理合同通过不能替代其他平台或实际桌面运行验收。

压缩或还原历史可能改变原生文件身份；没有连续性证明时保留旧账本并限制依赖该来源的动作，不复制转录文件或删除绑定来恢复资格。实际 Desktop 的 Hook 信任、续跑、受控写入和压缩恢复验收单独记录。

## 文件写入

仓库内绝对路径先规范化为相对路径，再检查越界、敏感路径和重解析点。原始命令摘要与目标、前态仍绑定原生 `tool_use_id`、会话及回合。别名不能覆盖身份、权限或工具安全字段；不参与决策的普通扩展元数据不会单独造成拒绝。

启用 Operation v2 后，第一次原生调用创建操作起点并返回 `prepare_native_operation`。返回的 `exact_parameters` 包含解释器、脚本和参数数组，执行方据此准备操作，再以新的原生调用重试原补丁。缺少检索词时由目标文件名生成默认词；不得伪造宿主 ID 或操作起点。

能力索引是定位辅助。部分覆盖、缺失或不可用时，记录 `index_verification=UNVERIFIED`，继续检查实际源文件、项目绑定和文件前态；不把损坏索引当成可信依据，也不改写它来制造通过。文件操作已核验不代表索引或业务语义已核验。

## 子代理与预算

新执行信封与复审控制器默认使用 GPT-6 Luna、Sol、Astra 的 low、medium、high；信息不足为 Sol/medium。主 Agent 的选择保持不变。LIGHT、STANDARD、STRICT 都消费已授权根账本中的额度，不由本次工具参数扩容。

空闲子代理续跑使用新许可，在原根、原工作谱系中预占和计费。运行中的子代理改走不启动回合的 `send_message`，避免检查后转为空闲时产生未预占的新回合。Agent ID、短名和规范路径只在本根验证过的身份映射中解析。

长记录以有界完整行窗口读取。末尾半行、迟到创建回执和迟到终态按同一个原生句柄恢复；旧回合不能结算新续跑。对账辅助记录损坏不阻止其他记录，也不清空预算。只有有来源的未启动证明才能按原账本规则处理预留，未知不能当作免费调用。

规划单位不是真实 credits。预算约束只对已接入的原生路径和已验证绑定成立；没有宿主强制或系统隔离证据时，必须标明策略约束或逻辑只读，不能声称系统只读。读取任务通过也不能证明所有写入口均被系统隔离。

## 验证与兼容

旧 V3/V4/V5 根按冻结策略回放。新控制器的显式旧策略选项用于兼容，不把历史资格评测重新变成新默认的前提。复审与交付分别记录源文件变化、检查、独立报告、提交、推送、安装与实际生效。

测试必须从安装器产物和实际注册入口验证行为，不能仅遍历策略目录自证覆盖。真实桌面验收需保持被测门禁开启；静态测试、安装文件一致或 Hook 返回空对象均不单独证明整个流程已生效。

原生事件契约以 [OpenAI Hook 文档](https://learn.chatgpt.com/docs/hooks)为参考；会话记录格式不是稳定接口，因此采用有界适配并保留未知状态。
