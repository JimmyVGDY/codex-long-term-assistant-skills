# V5.0 设计参考与落地原则

V5.0 延续 V4.2 的原则，不把外部资料原文复制进提示词，而是将 Codex 官方子 Agent、模型、Skills 和配置能力转化为可执行规则、状态工具、结构化协议与回归测试。

## 主要能力依据

- Codex 子 Agent：独立上下文、并行读取密集任务、自定义 Agent 和模型/推理强度配置；
- Codex Skills：先用名称与描述路由，选中后再加载完整 `SKILL.md` 与按需 Reference；
- Codex 模型：Luna 面向低成本明确任务，Terra 面向日常工程与复杂判断；更高推理强度通常增加耗时和 Token；
- Codex `[agents]`：默认子模型、默认推理强度、并发线程和中断消息配置；
- 请求方确认的使用偏好：主 Agent 通常使用 Terra，自动子 Agent 最高不得超过 Terra High。

## 落地原则

1. 给 Agent 一张短而稳定的全局地图，领域规则按 Skill 渐进加载；
2. 简单任务先由主 Agent 完成，只有独立收益高于协调成本时才派生；
3. 子 Agent 按 `luna-low -> luna-medium -> terra-medium -> terra-high` 逐级升级；
4. 人数、模型、推理强度、上下文和轮次同时纳入预算；
5. 审查包先摘要后展开，保留完整差异用于证据核验；
6. 相同 packet、相同 Reviewer、相同检查点内容受到幂等保护；
7. 独立上下文、逻辑只读与系统隔离分别记录，不能互相冒充；
8. 将反复失败的流程转化为脚本、Schema、检查器和测试，而不是继续膨胀全局提示词。
