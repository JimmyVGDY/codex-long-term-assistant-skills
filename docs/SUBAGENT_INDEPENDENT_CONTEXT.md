# Codex 子 Agent 独立上下文、模型与委派协议

## 核心能力

- 子 Agent 在独立上下文中处理专门任务，中间探索和大量读取不必全部进入主会话；
- 独立上下文不会自动获得父会话全部事实，主 Agent 必须提供最小、完整、无歧义的任务包；
- 每个子 Agent 都会产生模型与工具消耗，多 Agent 不天然省 Token；
- 独立上下文不等于权限隔离，系统只读必须由父会话或运行时证据确认。

## 最小委派包

1. 功能边界、目标与非目标；
2. 当前阶段、执行档位、风险和停止条件；
3. 基线、HEAD、packet hash 与 freshness；
4. 唯一职责、文件/符号/调用链范围和排除范围；
5. 已有验证、失败、未验证项和证据索引；
6. 允许与禁止操作、隔离等级；
7. 请求模型档位和结果 Schema。

## 返回主会话

- 已检查范围；
- 合并后的根因 findings；
- 证据等级、未验证项和必要验证；
- 实际模型、推理强度和隔离状态；
- 简短结论。

不得回传完整父会话、完整 diff、原始长日志、全部文件内容或内部推理过程。

## 模型路由

```text
luna-low -> luna-medium -> terra-medium -> terra-high
```

- Luna：读取密集、明确、重复、结构化的子任务；
- Terra Medium：业务语义、多文件逻辑和普通专业判断；
- Terra High：事务、并发、安全、不可逆迁移、核心状态机和阻塞冲突；
- 自动流程不得超过 Terra High，也不得使用 Sol、`xhigh`、`max` 或 `ultra`。

## Harness 原则

V7.3 采用“地图而不是千页手册”：全局规则负责边界与路由，Skills 负责按需能力，脚本负责状态、证据、幂等和门禁，仓库与外部记忆保存可验证事实。
