# Codex 子 Agent 独立上下文与委派模型

## 已确认能力

- 主 Agent 可以把专门子任务交给具有独立上下文的子 Agent；子 Agent 的探索、文件读取和中间工具结果不会全部进入主会话。
- 子 Agent 完成后只向主 Agent 返回最终结果或摘要，因此适合代码探索、日志分域分析、专业 Reviewer 和长输出隔离。
- 独立上下文不等于自动拥有全部父会话事实。主 Agent 必须提供最小、完整、无歧义的任务包。
- 独立上下文也不等于权限隔离。权限和工具限制必须按平台实际运行时验证。

## 最小委派包

1. 任务和功能边界；
2. 当前阶段、执行档位和风险；
3. 基线 Commit、diff 或审查 packet hash；
4. 相关文件和调用链入口；
5. 已执行验证、失败和未验证项；
6. 允许/禁止操作；
7. 唯一职责、输出 Schema、成本档位和停止条件。

## 返回主会话的内容

- 已检查范围；
- 结构化 findings；
- 证据等级和未验证项；
- 根因分组和必要验证；
- 简短摘要。

不得把完整工具日志、全部文件内容或冗长内部推理回传主会话。

## Harness 原则

V4.1 采用“地图而不是千页手册”：全局规则只定义边界和调度，Skills 提供按需能力，脚本负责状态、证据和门禁，仓库和外部记忆保存可验证事实。执行问题应优先转化为可运行工具、检查器和反馈回路，而不是继续向全局提示词堆规则。
